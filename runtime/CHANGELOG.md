| v0.9.7 | 2026-08-31 | **Sponza × Intel reference lighting parity (phase 1) + macOS/Metal bring-up**. Sponza scene calibrated against Intel's New Sponza reference renders (package `main1_sponza`): sun rotation now matches the glTF SUN node (elevation 55.9°, azimuth 79° — was 75° due +X), `SkyAtmosphere.sun_illuminance` unified with the directional light scale (was 20 vs 10 — independent scales made shade ~2× too bright), SkyLight `min_occlusion` 0.1 → 0.01 (was a hard irradiance floor 5–20× above the deferred shader's documented 0.005–0.02 range), dead `r.SSGI.Intensity` knob removed (master `r.SSGI` defaults false), GTAO enabled, and all 28 `materials/sponza/*.uzmat` artistic overrides (`roughnessMultiplier 0.55`, zeroed metallic, warm tint) reset to Intel-authored response. PhysCamera A/C/E entities replicate Intel's reference viewpoints (transforms converted Y-up→Z-up, meters→cm, vertical FOV 58.5/36.3/37.2°); the fly-camera controller that overwrote the camera every frame was removed. **Scene loader**: `ApplyDirectionalLightFields` now parses `atmosphere_sun_light`, `light_source_angle`, `shadow_cascades`, `cascade_distribution_exponent`, `dynamic_shadow_distance` (snake_case contract + camelCase aliases) and warns on unrecognized light keys — previously dropped silently. **Shadows**: `dynamicShadowDistance` now flows component → `LightFrameData` → `SetupShadowFrame` (was hardcoded 40000); sun disk angular radius uses half the source angle (was full angle as radius — disk 2.3× too large). **GI resource validity**: `SSGISettings.enabled` defaults false (matches `r.SSGI`), SSGI/DDGI result textures bind only after their first completed render/update (`HasProducedResult`/`HasCompletedFirstUpdate` — previously never-written textures were bound whenever the system was initialized), Radiance Cache trace gains `firstWrite` so the first probe dispatch replaces instead of blending 88% with undefined SH history. **macOS/Metal bring-up**: CMake+Ninja build works end-to-end with Apple Clang (zig 0.16 incompatibilities in build.zig patched with `@hasDecl`/Io-API guards; system libc++ on Apple); Metal backend compiles (all sources ObjC++, ARC where required) and renders — `triangle_demo` runs on Metal with portable RHI-readback screenshots; vendored submodules restored (entt, fastgltf+simdjson, meshoptimizer), lz4/etcpak/xatlas/msdfgen/libpng/libjpeg-turbo/spng/ufbx sources wired into CMake, `ShaderManager`/`ShaderPipeline`/`H264Encoder` report honest "unsupported platform" on non-Windows instead of failing to compile. NOTE: the full scene renderer on macOS still needs the Metal shader path (runtime HLSL compilation is Windows-only) — the Sponza visual comparison runs on Windows. |
| v0.9.6 | 2026-04-17 | **FBX axis fix: trunk torsion eliminated — skeleton + anim frames now live in the same engine frame**. Diagnosed by comparing `MushroomMonster_Low.uzskel` Point001 bind rotation `(0.7107, 0, 0, 0.7035)` (≈90° around +X) against `AS_Mushroom_Idle.uzanim` frame-0 rotation `(-0.5025, -0.4975, -0.5025, -0.4975)` (≈120° around (-1,-1,-1)/√3). Positions matched to ~1e-4, rotations were in completely different frames — classic signature of a bind/anim frame mismatch. **Root cause**: Maya mesh FBX uses Y-up RH cyclic remap `(x,y,z)→(z,x,y)` (det=+1); UE5-retargeted animation FBXs (`ApplicationName=Unreal Engine 5.6.1`, `UpAxis=Z`, `Front=-Y`) land in a Z-up frame with a T_left pre-rotation baked into the root that the previous `(-y,x,z)` remap didn't compensate. **Fix**: new closed-form two-sided quaternion sandwich in `RemapSrcQuat` for `MaxZupRH` — `q' = q_L · q_ue5 · q_R` where `q_L = (0, 0, √2/2, √2/2)` (+90° around engine Z from `M_maya * conj(T_left)`) and `q_R = (-0.5, -0.5, -0.5, 0.5)` (`M_maya^-1`), mathematically equivalent to the MayaYupRH `M_maya * q * M_maya^-1` conjugation for every bone in the chain. Derivation verified numerically on root (Point001), direct child (MushroomPelvis), and deep descendant (Point005). **Scale remap**: decoupled from position — scale magnitudes must never be negated, so MayaYupRH uses cyclic `(sz,sx,sy)` (no sign flip) and MaxZupRH uses `(sy,sx,sz)` (pure X↔Y swap). **Triangle winding flip restored** — removed in v16 on the assumption that det=+1 remaps preserved CCW, but LH rendering interprets RH-sourced CCW triangles as back-facing. For any non-Identity source convention the importer now swaps `triIndices[1]↔triIndices[2]` per triangle so outward-facing surfaces render correctly under LH back-face culling. Importer `Version()` bumped 16→17 — forces automatic re-cook of all FBX-sourced assets via the sidecar version check. |
| v0.9.5 | 2026-04-17 | **GPU skinning stable + 3rd-person controller + retargeted clips**. Skeletal animation now runs end-to-end on GPU at 480+ FPS with the mushroom monster fully animated and player-driven. **GPU skinning stability**: `SkeletalMeshInstance` grew a persistent UPLOAD-heap palette staging buffer (`m_gpuPaletteStaging` + `m_gpuPaletteStagingMapped`) allocated once in `EnsureGpuSkinningResources`; the per-frame upload is now `memcpy` + `CopyBufferRegion`. The previous per-frame `UploadContext::UploadBuffer` path fragmented D3D12MA fast enough to fail with `DXGI_ERROR_DEVICE_REMOVED` after a few hundred frames. **CPU fast path bypass**: `SkeletalMeshSubsystem::TickAll` now skips `UpdatePaletteFromPose()` + `SkinCpu()` when the GPU compute path is active — recovered FPS from 15 → 489 on the mushroom test scene (skinning 120k vertices on the CPU was useless when the GPU path was already running). **FBX importer v16**: per-source axis convention detection (`g_fbxSrcConv` thread_local) — Maya FBX (Y-up RH) and 3ds Max FBX (Z-up RH) now coexist in the same project. New `RemapSrcVec3`/`RemapSrcQuat`/`RemapSrcScale` helpers normalize all inputs to the engine's Z-up LH X-forward convention. `ExtractSkeleton` walks up the FBX hierarchy to include ALL transform-only ancestors (industry-standard root-above-pelvis); manual triangle-winding flip removed because per-source remaps preserve handedness (det=+1). `Version()` returns 16. **TRS composition**: `Skeleton::ComputeInverseBindMatrices` and `SkeletalMeshInstance::UpdatePaletteFromPose` now compose joints via `BoneTransform::ComposeWith` (T·R·S in that order) instead of raw `Mat4` multiplication, matching FTransform semantics and fixing scale-induced shear at deep joint chains. **Animation prefix aliasing**: clips named `AS_Mushroom_*` (UE5 retargeting source convention) and `Anim_*` are auto-stripped at registration AND aliased under both names so authors can reference either form. **Lua entity transform API**: `uz.scene.set_position(entity, x, y, z)`, `get_position`, `get_world_position`, `set_rotation(entity, qx, qy, qz, qw)`, `get_rotation`, `set_rotation_yaw(entity, yawRadians)` — implemented in `lua_entity_api.cpp` writing through `SceneComponent`. **Mushroom controller rewritten**: WASD locomotion (W=forward, S=back, A/D=turn) translates the entity along its facing axis at 220 cm/s; 3rd-person follow camera with right-mouse orbit + scroll zoom + framerate-independent smoothing (`1 - exp(-rate * dt)`), all action bindings preserved (Space/E/R attacks, F hit, Q block, X death). **Scene tweaks**: ground plane extended 800→4000 cm so you can roam freely; old `Controller` entity running `fly_camera.lua` removed; `MainCamera` repositioned behind character at `(-380, 0, 260)` so the very first frame doesn't snap-pan. |
| v0.9.4 | 2026-04-16 | **Skeletal bind-pose rendering + material graph fixes + scene renderer stability**. Skeletal mesh import now loads the mushroom character correctly in its rest pose. CPU skinning is temporarily bypassed (palette identity bug at bind pose still open) — the mesh renders from the stripped 48 B bind-pose stream primed by `SkeletalMeshInstance::Bind()`. **Perf (47 → 472 FPS)**: `SkeletalMeshInstance` grew an `m_outputDirty` flag; `SkeletalMeshSubsystem::UploadAll` now skips instances whose vertex data hasn't changed, avoiding a 5.76 MB `CreateBuffer` + `CopyBuffer` + `DestroyBuffer` round-trip every frame per character. **Geometry corruption**: `UploadContext::ReleaseStaging()` destroyed staging buffers immediately after `CopyBuffer`, so the GPU read freed memory and produced stray triangles across the screen. New `SceneRenderer::QueueBufferDestroy()` routes staging buffers through the per-frame `m_deferredDestroyBuffers` queue, which fires on the NEXT frame after the fence completes. `Shutdown()` now drains that queue too so the D3D12MA allocation-leak assert no longer fires on exit. **Material graph**: `.uzmat` authors commonly write `"srcPin": "RGB"` but `TextureSample` exposes outputs `["RGBA","R","G","B","A"]` — the resolver silently dropped `BaseColor`/`Normal` pins, compiling a PSO with 1 texture slot (ORM only) instead of 3. Added `"RGB"/"XYZ"/"XY"` alias → `"RGBA"` (Float4→Float3 swizzle already handled by `PromoteType`). **CLI `--view-mode`**: `uzengine.exe` uses its own `Config`-based parser distinct from `Application::ParseArgs` and never applied the flag — wired `configPtr->GetString("view-mode")` → `sceneRenderer.SetDebugViewMode()`. **Exposure**: `r.Exposure=3.0` was too aggressive for outdoor/sunlit scenes, blowing out highlights into fake-metallic sheen — default reduced; per-scene overrides via `postprocess_volume` remain the right path. **Mushroom `.uzmat` tuning**: the ORM texture's B channel was baked as `1.0` over stem UVs (authoring bug), so `metallicMultiplier=0.0` + tuned `roughness`/`specular` for organic response. |
| v0.9.3 | 2026-04-08 | **Path tracer: emissive GBuffer + reference specular model**. Wired GBuffer RT3 (emissive HDR) into the path tracer — HUD glows, emissive surfaces light correctly. Added `emissiveGBuffer`/`emissiveSrvIndex` to `PathTracerPassDesc` and expanded root constants to 9 DWORDs. Replaced screen-space ray marching (SSR) specular with a roughness-perturbed mirror model: `reflect(-V,N)` lerped toward a random hemisphere direction by roughness², sampled from the sky cubemap at `LOD=sqrt(roughness)*5`. Eliminates self-intersection artifacts on curved surfaces, dark floor streaks, and visor distortion. |
| v0.9.2 | 2026-04-06 | **Brixelizer GI shipped + indoor lighting recipe**. Wrapper DLL `runtime/thirdparty/amd-fidelityfx-1.1/wrapper/uz_brixelizer.dll` (MSVC CMake → 18 `uz_brix_*` C exports) hides FFX SDK 1.1.4 MSVC CRT/STL behind a runtime LoadLibrary boundary so Zig/mingw can drive Brixelizer. `brixelizer_loader.{h,cpp}` resolves all 18 entry points with macro rebinding so existing call sites are unchanged. Geometry registration bridge (138 Sponza meshes) caches per-mesh vbSlot/ibSlot via stable `outIndex` two-pass collection. Engine-owned 512^3 R8 SDF atlas (3D), brick AABBs structured buffer, per-cascade aabbTree+brickMap pairs, 256 MB scratch. **Critical fix**: `DX12CommandList::RebindBindlessHeaps()` called after every FFX dispatch — FFX rebinds the descriptor heap to its own internals, leaving the engine's bindless heap unbound and turning every downstream pixel black. The same pattern applies to any other third-party DX12 integration. `Config::FlushCvarOverrides()` runs BEFORE `SceneRenderer::Init` and is now idempotent so file-scope CVar overrides reach init-time gates. **Indoor lighting recipe**: Sponza skylight tuned for interior balance (`intensity=0.35`, `indirect_lighting_intensity=0.5`, `min_occlusion=0.04`, lower-hemisphere warm tint), contact shadows enabled by default at `r.ContactShadow.Length=0.10`, deferred lighting now REPLACES sky SH ambient with the Brixelizer diffuse atlas value when present (avoids double-counting indirect light). |
| v0.9.1 | 2026-04-06 | **Indoor Lighting System Phase 2 complete**: `LightProbeVolumeComponent` + JSON serializer + `IrradianceProbeGrid` (author-placed L2 SH grid, sky cubemap capture, trilinear deferred sample, Sponza scene with `InteriorProbeVolume`); `PerFrameCB` grown 768→1024 bytes for `lpv*` and `ddgi*` fields; CSM interior fast path (skip PCF when `sunNoL == 0`); real `radiance_cache_trace_cs.hlsl` (replaced 1-line stub: Hammersley sampling, 4-cascade GDF sphere-tracer, Sloan L2 SH accumulation, EMA hysteresis); temporal probe spreading (1024 probes/frame, full grid refresh every 4 frames via `g_probeOffset`/`g_probeBudget` root constants); **DDGI subsystem (Majercik 2019)**: `DDGISystem` class with octahedral irradiance (`RGBA16F` 2048×128) + depth (`RG16F` 4608×288) atlases, `ddgi_probe_update_cs.hlsl` writes both via DXR 1.1 `RayQuery<>` (cosine-weighted texel integration, EMA blend), deferred lighting Chebyshev visibility sampler with 8-probe trilinear blend, runtime-selected via `r.RayTracing.GI` CVar; Sponza @ 4.77 ms/frame (210 FPS RTX 4090) with the full pipeline including LPV + DDGI + radiance cache + GTAO + SSR + SSGI; 50 unit tests (49 pass) covering trilinear blend, DDGI atlas dimensions, `LightProbeVolumeComponent` defaults |

## Task Management (Rulebook)

All feature work uses Rulebook tasks. See `/.rulebook/specs/RULEBOOK.md` for full format.

### Task File Structure

| File | Content |
|------|---------|
| `proposal.md` | Why + what changes (detailed) |
| `tasks.md` | Simple checklist only (`- [ ]` / `- [x]`) |
| `specs/<module>/spec.md` | SHALL/MUST requirements, Given/When/Then scenarios |
| `design.md` | Architecture decisions (optional) |

**FORBIDDEN in `tasks.md`**: long explanations, specifications, technical details. Keep it to checklist items only.

### Task Workflow

```bash
rulebook task create <task-id>     # Create task structure
rulebook task validate <task-id>   # Validate format
rulebook task list                 # List all tasks
rulebook task show <task-id>       # Show details
rulebook task archive <task-id>    # Archive completed task
```

**Task creation is MANDATORY before implementing any feature.** See `.claude/rules/follow-task-sequence.md`.

### Task Locations

```
.rulebook/tasks/<task-id>/
├── proposal.md
├── tasks.md
├── design.md (optional)
└── specs/<module>/spec.md
```

## Quality Enforcement

These are NON-NEGOTIABLE:

1. **No test bypassing** — never `.skip()`, `.only()`, `@ts-ignore`, or comment out failing tests
2. **No hook bypassing** — never `--no-verify` on git commit/push
3. **No placeholder tests** — every test must assert real behavior
4. **Fix root causes** — never workarounds or symptom-level patches
5. **No temp files outside `/scripts`** — clean up immediately after use

### Post-Implementation Workflow

After completing any code change:
1. Quality checks (type check → lint → format → tests → coverage ≥ 95%)
2. Update `.rulebook/tasks/*/tasks.md` — mark `[x]` with description
3. Update docs if public API changed
4. Commit with conventional format: `<type>(<scope>): <description>`

**Commit messages MUST be in English.** Types: `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `build`, `ci`, `chore`.

## Project Knowledge

### Enforced Patterns

- 64-bit Packed Entity Handle (Lightuserdata)
- 64-bit Sort Key for Draw Command Batching
- C++/Lua API Naming Convention Parity
- Complete Implementation — Research First, Implement Fully
- Component Lifecycle (6 Stages) with Tick Groups
- DX12 SM6.6 Bindless Descriptor Heap (Target Architecture)
- Engine Logging via UZ_LOG with Category System
- G-Buffer Layout for Deferred PBR (5 Render Targets)
- Handle-Based Resource Management with Generational Counters
- Lua Registry-Based Pointer Injection
- Per-Entity Lua Environment Isolation
- Reference Engine Research Before Implementation
- Rust-Style Documentation Comments (`///` for C++)
- SceneProxy / Environment Gatherer Pattern
- Separate Compute Root Signature for GPU Bake Passes
- Static Library Build Order (Runtime → Demo)
- Thirdparty Dependencies via Setup Script Only
- Triple-Buffered CB Ring Allocator (256-byte aligned)
- Two-World Architecture (Game World + Render World)
- UE5 Source-First Implementation
- `uz::Application` Abstraction for Demos and Runtime
- Visual Verification via Demo + Screenshot + CompareGrid

Full details: `/.rulebook/knowledge/patterns/<slug>.md`

### Anti-Patterns to Avoid

- Blind GPU Debugging (Guess-and-Rebuild Loop)
- C++ Exceptions in N-API/Electron Addons
- DX11 SM5 Missing SetFragmentTexture for Non-Bindless Passes
- DX11 Stale SRV/UAV Bindings Between Render Graph Passes
- DX11 Write-Combined Memory Read-Back in CB Ring Allocator
- DX12/Vulkan/Metal Types Above RHI Boundary
- Invented Analytical Fallbacks
- Manual Thirdparty Cloning into `runtime/thirdparty/`
- Parallel File Edits in Same Conversation
- Switch-on-NodeType / If-Chains on Component Types
- TODOs, Stubs, and Placeholders in Implementation
- Unit Tests Only for Rendering Validation
- Using `git stash` for Uncommitted Work
- Vulkan Compute Dispatch Without Descriptor Flush
- Y-up Coordinate System in Shaders (UzEngine is Z-up)

Full details: `/.rulebook/knowledge/anti-patterns/<slug>.md`

## Tier 1 Prohibitions (Highest Precedence)

These override ALL other rules. See `/.rulebook/specs/TIER1_PROHIBITIONS.md` for full details.

1. **No shortcuts, stubs, or simplified logic** — implement the correct algorithm, completely
2. **No destructive git ops without authorization** — no `stash`, `rebase`, `reset --hard`, `push --force`
3. **No deletion without authorization** — never `rm -rf` or delete files/branches without asking
4. **Research before implementing** — never guess at bugs, APIs, or algorithms
5. **Sequential file editing** — one file at a time, never batch-edit
6. **No deferred tasks** — implement it now or explain why impossible
7. **Follow task sequence** — execute in defined order, no cherry-picking

This project uses persistent memory via Rulebook MCP and `.claude/projects/` memory files.

1. **Start**: Search memory for relevant context (`rulebook_memory_search`)

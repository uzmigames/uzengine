# Namespaced VFX Attributes

Scoped attribute storage for VFX effects, modelled after UE5 Niagara's
namespaced variable system (`Particles.*`, `Emitter.*`, `System.*`).
Foundation task for phase 7 Niagara-parity work — unblocks the system
parameter store (7.2.0), event pipeline (7.3.0), cross-emitter reads
(7.12.0), and several other DIs.

## Concept

A VFX effect is composed of values that live at three different lifetimes:

| Scope        | Lifetime              | Typical usage                                |
|--------------|-----------------------|----------------------------------------------|
| `Particles`  | Per-particle per-tick | `Position`, `Velocity`, `Color` ramps        |
| `Emitter`    | Per-emitter per-frame | `LoopCount`, `SpawnRate`, `Spread`           |
| `System`     | Per-system per-frame  | `Intensity`, `TeamColor`, `Age`              |

Binding a module to the right scope means the same HLSL snippet composes
naturally: a `ColorOverLife` module reads from `Particles.normalizedAge`,
a `SpawnBurst` module reads from `Emitter.loopIndex`, a parameter-driven
colour override reads from `System.teamColor`.

## CPU API — `VfxAttributeStore`

One container owns three isolated `VFXParameterStore` instances (one per
scope) and dispatches through a small typed API:

```cpp
#include "engine/vfx/parameters/vfx_attribute_store.h"

VfxAttributeStore store;
store.SetFloat(VfxAttributeScope::System,   "intensity", 2.0f);
store.SetVec3 (VfxAttributeScope::Emitter,  "windDir",   {1, 0, 0});
store.SetVec4 (VfxAttributeScope::Particles,"colorStart",{1, 0.5, 0, 1});

const float g = store.GetFloat(VfxAttributeScope::System, "intensity", 1.0f);
```

Key features:

- **Scope isolation.** `Particles.foo`, `Emitter.foo`, and `System.foo`
  are three independent keys — no accidental cross-scope clobbering.
- **Insertion-order preservation.** Each scope preserves the order in
  which attributes were first set. This determinism is required for
  stable CB layouts (see below).
- **Key-qualified convenience overloads.** `Set/Get` overloads taking a
  `VfxAttributeKey{scope, name}` for call sites that carry the pair
  around as data.
- **Canonical string form.** `VfxAttributeKey::ToString()` produces
  `"<Scope>.<name>"` (e.g. `"System.intensity"`) and
  `VfxAttributeKey::FromString()` parses it back. Used in JSON configs
  and the event-pipeline binding-override syntax.

## HLSL layout — `VfxAttributeHlslGen`

Each scope produces a deterministic HLSL `cbuffer` when its attributes
are flushed each frame. The default register slots follow the convention:

| Scope       | Register slot |
|-------------|---------------|
| `System`    | `b8`          |
| `Particles` | `b9`          |
| `Emitter`   | `b10`         |

`GenerateVfxAttributeCbuffer(store, cfg)` emits:

```hlsl
// Auto-generated by VfxAttributeHlslGen — do not edit directly.
// Scope: System, register: b8, attrs: 2
cbuffer VfxSystemAttributes : register(b8) {
    float4 _System_intensity;
    float4 _System_windDir;
};
float4 System_intensity() { return _System_intensity; }
float4 System_windDir()   { return _System_windDir; }
```

Scalar / Vec3 attributes still occupy a full `float4` slot — callers
swizzle at the use site. Future work (7.2.0) will add per-attribute type
tags so the generator can emit typed accessors returning `float` /
`float3` / `float4` directly.

CB upload uses `VfxAttributeStore::PackScopeToBuffer(scope, dst, size)`;
layout and byte order match the generator output verbatim.

## Migration port — reference fields

Three existing `ParticleEmitter` fields are slated to move to the
`System` scope as the reference port (task 7.1.0 item 2.2):

| Old field            | New key                  |
|----------------------|--------------------------|
| `emitterDuration`    | `System.duration`        |
| `loopCount`          | `System.loopCount`       |
| `vfxTotalTime`       | `System.age`             |

Once the scope-qualified CB is wired into the render-graph dispatch, the
compound system instance will populate `System.*` once per frame and the
individual emitters will drop these fields from their local configs.
Compound-level parameter binding (7.2.0) then gets this machinery for
free.

## Testing

- `runtime/tests/engine/vfx/test_vfx_attribute_store.cpp` — 16 tests
  covering scope isolation, typed round-trips, enumeration,
  Clear/ClearAll, and `PackScopeToBuffer` layout determinism.
- `runtime/tests/engine/vfx/test_vfx_attribute_hlsl_gen.cpp` — 6 tests
  covering empty-scope short-circuit, insertion-order emission, register
  override, custom struct name, run-to-run determinism, and the default
  register-slot convention.

# Brixelizer GI enablement: 2026-10-14

Brixelizer GI now builds, loads, creates both real FidelityFX contexts on the
NVIDIA GeForce RTX 5080, and contributes diffuse indirect light in Sponza.
`r.BrixelizerGI` remains false by default. No commit or archive was made.

## Builds

The installed CMake 4.3.2 and Visual Studio 2022 BuildTools (MSVC 19.44.35226)
worked. SDK configuration initially failed because the vendored binary
dependencies were absent, not because CMake was incompatible.

Restored prerequisites:

- `sdk/libs/pix/bin/x64/WinPixEventRuntime.{dll,lib}` from the SDK-documented
  [WinPixEventRuntime 1.0.240308001 NuGet package](https://api.nuget.org/v3-flatcontainer/winpixeventruntime/1.0.240308001/winpixeventruntime.1.0.240308001.nupkg).
- `sdk/tools/binary_store/FidelityFX_SC.exe`, `dxcompiler.dll`, `dxil.dll`, and
  `D3D12Core.dll` from the official
  [FidelityFX-SDK v1.1.4 binary_store](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/tree/v1.1.4/sdk/tools/binary_store).
  DXC did not need to be on PATH: the SDK shader compiler loads its adjacent DLLs.

Exact successful build commands, starting in `runtime`:

```sh
cd thirdparty/amd-fidelityfx-1.1/sdk
cmake -B build -G "Visual Studio 17 2022" -A x64 -DFFX_API_BACKEND=DX12_X64 -DFFX_ALL=ON -DUZ_BRIXELIZER_OCT_NORMALS=ON
cmake --build build --config Release --parallel 16
cd ../wrapper
cmake -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --parallel 16
cd ../../..
zig build -Doptimize=ReleaseFast
```

The SDK produces `sdk/bin/ffx_sdk/ffx_backend_dx12_x64.lib`,
`ffx_brixelizer_x64.lib`, and `ffx_brixelizergi_x64.lib`. The wrapper produces
`wrapper/build/bin/uz_brixelizer.dll`. `runtime/build.zig` now deploys that DLL,
the PIX runtime, and the Agility DLLs required by the system serializer.
The build prints `Brixelizer GI: UZ_BRIXELIZER_ENABLED=1 (wrapper DLL found)`.
A fresh `.zig-cache-brixelizer-active` cache was used for final verification.

## Context creation diagnosis

The DLL initially loaded and bound all 18 entry points, but
`ffxBrixelizerContextCreate` returned `-2147483635`
(`0x8000000D`, `FFX_ERROR_BACKEND_API_ERROR`). Temporary backend diagnostics
identified the exact failing operation:

```text
FFX DX12: SerializeRootSignature failed hr=0x887E0003 pipeline=FFX_BRIXELIZER_PASS_CASCADE_MARK_UNINITIALIZED
```

This was `D3D12_ERROR_INVALID_REDIST`. The executable exports
`D3D12SDKPath = ".\\D3D12\\"`, while the build deployed `D3D12Core.dll` only at
the executable directory's root. The engine's explicit device factory worked,
but the FFX system serializer followed the exported, missing directory.
Deploying `D3D12Core.dll` and `d3d12SDKLayers.dll` into `build/bin/D3D12/`
made both contexts create on the RTX 5080. Deployment is now automatic when
the Brixelizer DLL gate is enabled. Temporary SDK diagnostics were removed.
No vendor restriction, scratch-size change, or ABI workaround was needed.

The real path also needed its disabled constructor and dispatch restored,
with opt-in gates; actual returned vertex/index buffer slots; world-space
instance bounds; replacement of changed registrations; owned GI backend
scratch memory; all static/dynamic/merged cascade resources; correct
four-byte FFX buffer strides; correct view/projection inputs, cube and depth
descriptions, roughness channel, octahedral normal decoding, uploaded noise,
history copies, and render-graph output dependencies.

## Tests and coverage argument

Final command:

```sh
zig build test -Doptimize=ReleaseFast --cache-dir .zig-cache-brixelizer-active > build/brixelizer-active-gtests-final.log 2>&1
```

Final output: 7,686 tests from 754 suites, 7,664 passed, 19 skipped, and exactly
the three pre-existing failures
`VfxEditorSlate.{WorkbenchHasTwoColumns,TitleBarReflectsEmitterName,StatusBarBindingsReflectTelemetry}`.
The command exits 1 for those failures. All 12 Brixelizer tests passed in
this final single run, with none skipped.

The three real GPU tests are:

- `BrixelizerGIGpuTest.RegistersActualWorldSpaceInstanceDescriptions`:
  forwarding observers inspect real FFX descriptors and buffer registrations;
  both index formats, distinct returned slots, stride/count/offset/format,
  reflection/nonuniform scale/translation, world AABB, invalid mesh skipping,
  unchanged-registration caching, transform replacement, and empty-list deletion.
- `BrixelizerGIGpuTest.CreatesRegistersBakesAndDestroysRealContexts`:
  real context creation, separate backend scratch allocations, one mesh,
  real bake and GPU update, six raw cascade pairs for two logical cascades,
  atlas and buffer sizes/strides, `GetDeviceRemovedReason() == S_OK`,
  real destroy results, released output resources/allocations/descriptors,
  and repeated shutdown. GI compute dispatch is disabled only in this
  bake-focused fixture; the Sponza run exercises it.
- `BrixelizerGIGpuTest.InitializedMoveAndReinitPreserveOwnership`:
  initialized move construction, assignment over a live context, reinit,
  actual old-context destruction, resource ownership, and final shutdown.

The nine retained public API tests cover default sentinel outputs, null and
zero-extent rejection, repeated shutdown and rejected-init cleanup, geometry
registration before init with null/empty inputs, execute before init, resize
before init, and uninitialized move construction/assignment.

The on/off renders additionally cover master gating, real GI dispatch,
depth/normal/roughness/environment inputs, temporal history, engine descriptor
heap restoration, output transitions, deferred diffuse adoption, and actual
GPU contribution. The SDK shader build covers the oct-normal adapter.

This is the requested enumerated-test coverage argument. It is not native
instrumented coverage data and cannot certify a numerical 95% threshold.
Allocation/upload failure injection and initialized resizing were not covered
by these tests. Item 8.6 remains unticked rather than inventing a percentage.
Clangd is unavailable; native compilation and the suite validated the C++.

# Shader Improvement Analysis: Shadows, GI, Atmosphere

Deep comparison of UzEngine shader implementations versus Falcor and published
references (Hillaire 2020, Bruneton 2017, Fernando 2005, Wright 2015, Majercik 2019).
Each entry identifies the current implementation, the gap, the priority, and the
authoritative reference.

---

## Part 1 — Shadow Shaders

| File | Function / Algorithm | Current Implementation | Improvement Opportunity | Priority | Reference |
|------|---------------------|----------------------|------------------------|----------|-----------|
| `shadow_common.hlsli` | `SampleShadowCascade` — PCF kernel | 16-tap Poisson disk with static offsets. Penumbra radius is a depth-proportional heuristic (`projCoords.z * 3.5`). No jitter/rotation. | Replace static Poisson disk with **per-pixel rotated** Poisson disk using interleaved gradient noise (same noise as SSGI uses). Static offsets alias at low screen-space frequencies. Rotation breaks the pattern even without TAA. | HIGH | Jimenez 2014 "Next Generation Post Processing in Call of Duty" — IGN-rotated PCF |
| `shadow_common.hlsli` | `SampleShadowCascade` — NdotL bias | `SampleShadowMap` (no-NdotL overload) hardcodes `NdotL = 0.5`. This uses fixed bias regardless of surface slope. | Remove the `NdotL = 0.5` fallback. Both `SampleShadowMap` and `SampleShadowMapFull` exist; callers should always use `SampleShadowMapFull`. Alternatively, pass NdotL through the CB or compute from stored GBuffer normal in the deferred pass. | HIGH | Holbert 2011 "Normal Offset Shadows" |
| `shadow_common.hlsli` | `SampleShadowCascade` — penumbra calculation | Penumbra computed from `projCoords.z * 3.5` (scene depth proxy), not from actual blocker depth. This creates uniform penumbra width per-cascade regardless of true occluder distance. | Perform a **2-tap blocker search** (min and max shadow depth) to estimate average occluder depth before PCF. Scale the PCF kernel from the ratio `(receiverDepth - avgBlockerDepth) / avgBlockerDepth * lightSize`. This is the PCSS approach but with fewer search samples (~4) for non-PCSS quality levels. | MEDIUM | Fernando 2005 "PCSS"; Engel 2006 "CSM" |
| `shadow_common.hlsli` | `SampleLocalLightShadow` — single PCF tap | Point/spot lights use a single `SampleCmpLevelZero` call with a constant depth bias. Binary shadow result; no soft edges. | Add a 4-tap rotated PCF kernel for local light shadows, matching the CSM quality. One `SampleCmpLevelZero` per sample. Use the same rotated Poisson offsets as the directional shadow. | MEDIUM | Donnelly & Lauritzen 2006 "VSM" |
| `shadow_common.hlsli` | ESM / EVSM | Not implemented. UzEngine uses only PCF comparison sampling. | Add an **EVSM** (Exponential Variance Shadow Maps) path selectable via `filterMethod` CB field (currently unused value 2). EVSM stores `exp(c * depth)` and `exp(c * depth)^2`, enabling GPU-filtered soft shadows at 1 bilinear tap via Chebyshev inequality. Eliminates the Poisson disk loop for the "soft" quality tier. Falcor uses EVSM natively for its primary shadow technique. | LOW | Salvi 2008 "Rendering Filtered Shadows with Exponential Shadow Maps" |
| `shadow_debug.hlsli` | Debug grid | All functions are stubs returning identity. The grid tile dispatch never shows cascade/shadow data. | Implement the full 3x3 grid as documented in `gpu-debugging.md` rules. Each tile should visualize the corresponding G-Buffer/shadow channel. The stub defeats the primary diagnostic tool for shadow debugging. | HIGH | Internal tooling — `gpu-debugging.md` rule §Buffer Visualization Grid |
| `pcss.hlsli` | `SampleShadowPCSS` — elliptical PCF kernel | Uses circular disk sampling (concentric disk approx). The PCSS reference uses an elliptical kernel derived from gradient analysis of the shadow receiver plane to produce anisotropic penumbras matching the occluder silhouette shape. | Implement the covariance-based **elliptical PCF kernel**. Compute the 2×2 shadow UV gradient matrix (ddx/ddy of shadowPosition in tile UV space), convert to ellipse parameters, and stretch the Sobol disk samples along the principal axes. This is PCSS_ANTI_ALIASING_METHOD=1 in the reference. | LOW | Fernando 2005 §PCSS elliptical kernel; Annen 2008 "Exponential Shadow Maps" |
| `pcss.hlsli` | `SampleShadowPCSS` — pixel quad message passing | No sharing of blocker search results across 2×2 pixel quads. Each pixel independently runs the full 16-sample blocker search. | Add 2×2 quad broadcasting via `QuadReadAcrossX` / `QuadReadAcrossY` intrinsics (HLSL SM6.0+). Average the 4 quads' blocker depth estimates and use that as the shared search result. Halves effective blocker search cost at no quality loss. | LOW | Fernando 2005 §pixel quad message passing; HLSL SM6.0 quad wave intrinsics |
| `pcss.hlsli` | `SampleShadowPCSS` — temporal jitter | No frame index parameter. `SobolPixel` uses only screen position for the base, so samples are identical every frame. | Add `View.StateFrameIndexMod8` (or UzEngine equivalent frame counter mod 8) to the Sobol base. This jitters the sample pattern per frame, allowing TAA to average over 8 different shadow sample sets — effectively 16 × 8 = 128 effective PCF samples at 4× lower per-frame cost. | MEDIUM | Fernando 2005 — temporal accumulation pattern |
| `contact_shadows.hlsli` | `ComputeContactShadow` — step count | Fixed 12 steps (`kContactShadowSteps`). Uniform step size regardless of ray length. | Scale step count with `rayLength` to maintain constant step density across different `rayLength` values. At large `rayLength` the 12-step resolution becomes sparse and misses thin geometry. Use 16 steps minimum, or reduce to 8 for short rays when temporal accumulation is active. | LOW | Wihlidal 2017 "4K Checkerboard Rendering in Battlefield 1" |
| `contact_shadows.hlsli` | `ComputeContactShadow` — thickness test | Binary threshold `kContactShadowThickness = 0.01` (1% of depth range). Thin walls produce false positives when rayDepth barely clips behind geometry. | Use a view-space thickness estimate instead of NDC: convert `kContactShadowThickness` from depth space to view-space units using `LinearizeDepth` before the comparison. This makes the threshold physically constant (e.g., 5 cm) regardless of camera distance. | LOW | Wihlidal 2017 §depth-space thickness |
| `depth_common.hlsli` | `LinearizeDepthReversedZ` | Standard formula. Correct and complete. | None. | — | Williams 1978 "Casting Curved Shadows" |
| `shadow_depth_vs.hlsl` | Vertex transform | Minimal and correct. No slope-scale depth bias applied at the vertex stage. | Add optional **slope-scale depth bias** via a `slopeScaleBias` root constant (default 0). Standard technique to reduce shadow acne on angled surfaces without requiring normal-offset bias in the pixel shader. Computable as `slopeScaleBias * max(|dz/dx|, |dz/dy|)` in rasterizer state rather than shader, but a uniform bias offset here can supplement it. | LOW | Williams 1978; standard DX12 rasterizer state SlopeScaledDepthBias |
| `dfs_cone_trace_cs.hlsl` | `TraceSdfObject` — worldToVolumeScale | `worldToVolumeScale` is computed but the result is always `1.0f` or `0.0f` because the else branch sets it to `0.0f` (dead code — `maxVolumeExtent` is never `<= 0.0001f` for a valid mesh). | Fix the world-to-volume scale computation: `worldToVolumeScale = 1.0f / maxVolumeExtent`. This matches the reference Wright 2015 formula `WorldToVolumeScale = 1/max3(VolumeToWorldScale)`. The bug means `tanLightAngle` is passed into `TraceSdfObject` in world units but cone radius computation assumes volume-space units — causes incorrect penumbra for non-unit-scale objects. | HIGH | Wright 2015 "Dynamic Occlusion with SDFs" §shadow ray trace:118 |
| `dfs_cone_trace_cs.hlsl` | `TraceSdfObject` — force-to-shadowed at max steps | `minConeVisibility = min(minConeVisibility, 1.0f - stepIndex / maxSteps)`. For high-quality (maxSteps=64) rays this fires only at step 64, adding ~1.5% incorrect shadow contribution in dense SDF regions. | This is the correct reference behavior. The formula should produce values in `[0, 1 - 1/N]` where N = maxSteps. When `N=64` the max error is 1.5% which is acceptable. No change needed; document the intentional behavior. | — | Wright 2015 §shadow ray trace:209 |
| `dfs_cone_trace_cs.hlsl` | AABB culling vs tile-based scatter | Per-pixel AABB test for every culled object. Reference uses a pre-pass that scatters object indices to shadow tiles (64x64 pixels), then the cone trace reads only objects assigned to its tile. | Implement **tile-based scatter culling** for DFS: add a `dfs_tile_scatter_cs.hlsl` pass that writes object indices into per-tile lists. The cone trace reads only its tile's object list. Reduces memory bandwidth and divergence in the cone trace loop from O(allObjects) to O(visibleObjectsPerTile). | LOW | Wright 2015 §ScatterObjectsToShadowTiles |
| `dfs_upsample_cs.hlsl` | Bilateral upsample | Exact reference bilateral algorithm. Correct implementation. | No improvements needed for the core algorithm. Consider adding a **view-space normal weight** to supplement depth proximity, which prevents bleed at depth-discontinuity edges where both sides have similar depths but different SDF shadow values (e.g., horizontal floor meeting a vertical wall). | LOW | Wright 2015 §upsample pass |
| `dfs_cull_objects_cs.hlsl` | AABB vs sphere hull test | Sphere-vs-convex-hull for directional, sphere-vs-sphere for point/spot. AABB box test substituted for sphere test in directional path. | The directional path uses `ShadowConvexHullIntersectBox` (tighter), which is correct and matches the reference "AABB vs separating axis" approach. No change needed. Document that the sphere test (`ShadowConvexHullIntersectSphere`) is provided but not used in the directional path for intentional tightness. | — | Wright 2015 §CullObjectsForShadowCS |

## Part 2 — GI Shaders

| File | Function / Algorithm | Current Implementation | Improvement Opportunity | Priority | Reference |
|------|---------------------|----------------------|------------------------|----------|-----------|
| `sdf_common.hlsli` | `SphereMarchMeshSDF` — max steps | Fixed 64 steps for all mesh SDFs. 64 steps through a 32^3 voxel grid is adequate. | For larger mesh SDFs (e.g., 64^3 baked for large objects), 64 steps may miss features. Use `maxSteps = max(resolution, 64)` or pass quality tier via a define. However, since mesh SDF bake is 32^3, 64 is fine at runtime. No change needed for current resolution. | — | Hart 1996 "Sphere Tracing" |
| `sdf_common.hlsli` | `SphereMarchGlobalSDF` — voxel resolution | Hardcodes 64 voxels per axis (`voxelExtent = extent * 2.0f / 64.0f`). Not parameterized by actual texture resolution. | Pass the voxel resolution as a parameter instead of hardcoding 64. If the global SDF resolution is increased to 128^3 for improved quality, the shader would still trace with 64-voxel step sizes, leading to gaps. | MEDIUM | Wright 2015 §GDF utility |
| `sdf_common.hlsli` | `LineBoxIntersect` — API mismatch | Takes `rayOrigin, rayDir` (unlike `dfs_cone_trace_cs.hlsl` which expects `rayOrigin, rayEnd`). In `dfs_cone_trace_cs.hlsl`, `LineBoxIntersect` is called with `(volumeRayStart, volumeRayEnd, ...)` — passing an endpoint as a direction, which is incorrect. | **Critical bug**: `dfs_cone_trace_cs.hlsl:144` calls `LineBoxIntersect(volumeRayStart, volumeRayEnd, localBoxMin, localBoxMax)` but `LineBoxIntersect` in `sdf_common.hlsli` interprets the second argument as a direction. Since `volumeRayEnd` is a world position (not a direction vector), the AABB intersection is wrong for objects not at the origin. Fix: pass `volumeRayDir = normalize(volumeRayEnd - volumeRayStart)` to the intersection function, or add a dedicated `LineBoxIntersectEndpoints` overload. | HIGH | Williams et al. 2005 "An Efficient and Robust Ray–Box Intersection Algorithm" |
| `radiance_cache_common.hlsli` | `EvaluateProbeSH` — SH packing layout | Reads L0 as `rSH0.w` (4th component). The packing defined in the comment says `[0] = (R_L00, R_L1x, R_L1z, R_L1y)` with L00 in `.x`. The eval then does `dot(rSH0, float4(1.0, N.x, N.z, N.y))` which uses the `.x` component for the L00 weight — but the loading code reads `rSH0.w` as L00 implicitly via the 4D dot. Verify that `R_L00` is at `.x`, not `.w`. | Verify the index-to-component mapping in both `PackSHToFloat4` (radiance_cache_trace_cs.hlsl) and `EvaluateProbeSH`. The packing in the tracer stores `packed[0] = float4(shR[0], shR[3], shR[2], shR[1])` meaning L00 is at `.x`. The evaluator uses `dot(rSH0, float4(1.0, N.x, N.z, N.y))` — this weights L00 by 1, L1x (`.y`) by N.x, etc. This is correct. **No bug**, but add explicit comments mapping each float4 component to its SH coefficient to prevent future confusion. | LOW | Ramamoorthi 2001 "Efficient Representation for Irradiance Environment Maps" |
| `sh_irradiance.hlsli` | `GetSkySHDiffuse` — L1 channel order | Uses `float4(kA1*N.x, kA1*N.y, kA1*N.z, kA0)` and dots with `float4(SH[0].xyz, SH[0].w)`. The order packs (L1_-1, L1_0, L1_1, L0_0). | Verify channel order against the SH packing written by the IBL baker and CPU-side sky SH computation. If the CPU packs SH[0] as (L1x, L1y, L1z, L0) and the shader evaluates as (x, y, z, 1.0 weight on .w), the coefficient ordering must match. Add explicit documentation of which coefficient occupies each float4 channel. | LOW | Sloan 2008 "Stupid Spherical Harmonics Tricks" |
| `ssgi_trace_cs.hlsl` | `CastScreenSpaceRay` — linear march | Simple linear step march in UV space. No hierarchical depth (`HiZ`) traversal. Misses intersections with thin geometry between steps. | Implement **Hi-Z screen-space ray tracing**: build a depth mip chain (max-depth pyramid), then traverse from coarse to fine mips to find the first intersection. Reduces average step count from 12 to ~5-6 for most rays. This is the standard SSGI optimization used by McGuire & Mara 2014 and all shipping SSGI implementations. | HIGH | McGuire & Mara 2014 "Efficient GPU Screen-Space Ray Tracing" |
| `ssgi_trace_cs.hlsl` | `CastScreenSpaceRay` — depth comparison tolerance | `compareTolerance = abs(stepUVz.z) * 2.0f` — a fixed multiple of the depth step. In reversed-Z, depth step size varies non-linearly with distance. At close range the tolerance is too tight (misses hits), at far range it's too loose (false hits). | Use a **view-space thickness threshold** (e.g., 20 cm) instead of a NDC-proportional tolerance. Convert the threshold: `compareTolNDC = thickness * depthDerivative`. This matches the approach in McGuire & Mara 2014 §3.2. | MEDIUM | McGuire & Mara 2014 §3.2 depth comparison |
| `ssgi_trace_cs.hlsl` | Ray count | `SSGI_RAY_COUNT = 8` at Q2. Falcor uses path tracing with 1 ray per pixel per frame accumulated over many frames via SVGF or ReSTIR. | Expose quality tiers 0-4 with 2/4/8/12/16 rays. Q0 (2 rays) for VR/mobile, Q4 (16 rays) for high-quality static lighting. The current Q2 (8 rays) is the correct default. No change needed to the count, but expose the quality tiers via shader permutations (`SSGI_RAY_COUNT` define). | LOW | Jimenez 2016 "Screen-Space Indirect Lighting" |
| `ssgi_trace_cs.hlsl` | `SamplePrevColor` — single mip | Mip level ramps from `SSGI_START_MIP_LEVEL=1` to `1 + (i/12)*4 = ~5` at max ray distance. The prev-color mip chain is generated by `prev_color_reduce_cs.hlsl` but **only mip 0 is generated** (single 2× downsample). Higher mip levels fall back to the hardware's undefined behaviour or return invalid data. | Fix `prev_color_reduce_cs.hlsl` to generate a full mip chain (mip 0 through 4). The shader already reserves UAV indices for mips 1-4 but leaves them unimplemented ("future single-pass downsampler"). Until the full mip chain is generated, cap `hitMipLevel = SSGI_START_MIP_LEVEL` (1.0) to prevent reading from uninitialized mip levels. | HIGH | Stachowiak 2015 "Stochastic Screen-Space Reflections" §prev frame reduce |
| `ssgi_spatial_denoise_cs.hlsl` | Spatial filter — kernel radius | Fixed `KERNEL_RADIUS = 4.0` pixels, always applied. No luminance-based or variance-guided radius adaptation. | Add **variance-guided radius scaling** (SVGF-inspired): compute the local variance from the 3×3 neighborhood during the neighbor loop, then scale the kernel radius inversely with variance. High-variance (noisy) regions get a larger kernel; low-variance (converged) regions get a tighter kernel. This is the key insight from Schied et al. 2017 SVGF. | MEDIUM | Schied et al. 2017 "Spatiotemporal Variance-Guided Filtering" §spatial reconstruction |
| `ssgi_spatial_denoise_cs.hlsl` | Spatial filter — wavelet passes | Single spatial pass with 8 samples at 4-pixel radius. SVGF uses 5 hierarchical wavelet passes (À-trous filter) with exponentially growing kernel spacing (1, 2, 4, 8, 16 pixels). | Implement a **multi-pass À-trous filter** replacing the single-pass Poisson disk. Each pass uses the same 3×3 bilateral kernel but with sample spacing `2^passIndex` pixels. 5 passes at cost of 5 × 9 = 45 texture reads vs current 9 reads — but provides much better denoising for the same number of input rays. | MEDIUM | Schied et al. 2017 §À-trous wavelet filter |
| `ssgi_temporal_accum_cs.hlsl` | Neighborhood clamp — AABB vs variance clip | Uses simple min/max AABB clamping. Variance clipping (SVGF/Salvi) uses the mean ± N×σ ellipsoid instead of the bounding box, reducing over-clamping and ghosting at fine detail. | Replace AABB clamping with **variance clipping**: compute mean (μ) and variance (σ²) of the 3×3 neighborhood, then clip the history sample to the [μ - γσ, μ + γσ] interval (γ ≈ 1.0). This is less aggressive than AABB clamping and preserves more temporal history in low-variance regions. | MEDIUM | Salvi 2016 "An Excursion in Temporal Supersampling" §variance clipping |
| `ssgi_temporal_accum_cs.hlsl` | Temporal weight — fixed alpha | `TEMPORAL_BLEND_ALPHA = 0.05` always (except disocclusion). No sample count tracking; the filter effectively acts as an exponential moving average with a fixed τ. | Track an **accumulated sample count** per pixel (1/alpha = N). For the first few frames after disocclusion, increase alpha to converge faster. After ~20 frames, decrease alpha to 0.05 for stability. Store the sample count in the alpha channel of the history buffer. This matches the SVGF moment buffer approach. | LOW | Schied et al. 2017 §temporal filter |
| `ssgi_upsample_cs.hlsl` | Bilateral upsample — 4-tap only | Samples only the 4 nearest half-res texels. At depth discontinuities all 4 taps may be on the "wrong" side of the edge, causing leaking. | Add a **5th fallback tap** at the exact nearest-neighbor (no bilinear fractional weighting) that activates when `totalWeight < threshold`. This guarantees a valid result at hard edges without requiring a more expensive search. Currently the nearest-neighbor fallback is triggered only at `totalWeight < 1e-6`, which is too conservative — leaking from slightly wrong side occurs before that. | LOW | Jimenez 2016 §bilateral upsample |
| `prev_color_reduce_cs.hlsl` | Mip chain generation | Generates only mip 0 (half-res from full-res). Mip 1-4 UAV indices are reserved but unused. | Implement **single-pass mip generation** using groupshared memory: write mip 0, then each 2×2 group of threads reads from groupshared to produce mip 1, 4×4 for mip 2, etc. Avoids 4 additional dispatch calls. Alternatively, use `SPD` (FidelityFX Single Pass Downsampler) which handles the full mip chain in one compute pass using LDS. | HIGH | GPUOpen FidelityFX SPD; Stachowiak 2015 §prev frame reduce |
| `mesh_sdf_bake_cs.hlsl` | Brute-force O(V×T) bake | Every voxel scans all triangles. Acceptable for 32^3 with <10K triangles, but scales poorly. A 64^3 grid with 50K triangles = 3.2B comparisons. | Add a **BVH-based bake** for large meshes: partition triangles into a flat BVH on CPU, upload BVH nodes as a StructuredBuffer, traverse on GPU. The reference Wright 2015 uses a BVH for this. Keep brute-force for meshes with <10K triangles as a fast path. | MEDIUM | Wright 2015 "Dynamic Occlusion with SDFs" §mesh SDF generation |
| `global_sdf_composite_cs.hlsl` | World-space AABB culling | Uses `boxDist > minDist` to skip distant meshes. The culling is correct but runs in world space using the mesh volume's `origin` — which is in **local object space** for meshes with non-identity transforms. | Bug: `meshMin = mesh.origin - mesh.extent` uses `origin` as the volume center in local space, but `worldPos` is in world space. The transform is applied inside `SampleMeshSdfLocal` but not in the AABB cull. The early-out cull can incorrectly reject transformed meshes. Fix: add world-space bounding box from the transformed corners of the SDF volume to the `MeshSdfDesc` and cull against that. | HIGH | Wright 2015 §GDF composite |
| `radiance_cache_trace_cs.hlsl` | GDF trace — fixed 32 march steps | `kMaxMarchSteps = 32` for the GDF sphere march inside each radiance probe ray. For a probe at the edge of the first GDF cascade (extent ~1000 cm) tracing across the full volume, 32 steps with 1-voxel minimum step size (= 31 cm for 64^3 / 2000 cm) gives ~992 cm coverage — sufficient but tight. | Increase to 64 steps to match `SphereMarchGlobalSDF`'s 128 steps. With 32 steps, rays through occluded passages can miss narrow geometry. The cost increase is acceptable given that only 32 rays × 4096 probes = 131K probe rays per frame are traced. | LOW | Majercik et al. 2019 "DDGI" §probe ray tracing |
| `radiance_cache_trace_cs.hlsl` | Probe hit shading — single-bounce only | Hit radiance = `lightCol * groundAlbedo * NdotL / PI + skyColor * groundAlbedo`. Uses a uniform `g_groundAlbedo` for all hit surfaces; no per-surface albedo lookup. | This is a known limitation of GDF-based probes (no per-surface albedo in the SDF). To improve accuracy, add a **sky occlusion weight**: trace a secondary visibility ray toward the sky direction and weight the ambient term by the GDF value at that point. This simulates sky occlusion on hit surfaces without requiring full path tracing. | LOW | Wright 2021 "Radiance Caching for Real-Time GI" §hit shading |
| `radiance_cache_trace_cs.hlsl` | Probe grid — uniform single grid | Single uniform grid with no clipmap hierarchy. Camera-distant probes have the same density as near probes. | Add **2-level clipmap** support: a fine grid near the camera (e.g., 16^3 at 80 cm spacing covering 1280 cm) and a coarse grid further out (16^3 at 400 cm spacing covering 6400 cm). The existing `SampleRadianceCache` trilinear interpolation works with both grids; the deferred lighting pass selects the finer grid by distance. | MEDIUM | Wright 2021 §radiance cache clipmaps |

| `transmittance_lut_cs.hlsl` | Ozone layer | Implemented via piecewise-linear tent distribution. Parameters from `OzoneParams` CB match the Hillaire 2020 reference. | No improvement needed. The ozone model is correctly parameterized. | — | Hillaire 2020 §ozone absorption |
| `multi_scatter_lut_cs.hlsl` | `NUM_DIRECTIONS = 64, NUM_STEPS = 20` | Hillaire 2020 reference uses 64 directions and 20 steps. Exact match. | No change needed. The multi-scatter LUT is correctly implemented per Hillaire 2020 §4.1. | — | Hillaire 2020 §multi-scattering LUT |
| `multi_scatter_lut_cs.hlsl` | Ground albedo | Uses isotropic phase `1/(4π)` for the multi-scatter LUT (correct per Hillaire 2020). No ground albedo contribution in the multi-scatter LUT (ground bounce not included). | Hillaire 2020 includes a Lambertian ground reflectance term in the multi-scatter LUT generation. | `sky_cubemap_cs.hlsl` | Mie phase function | Uses Hillaire 2020 Mie phase (single HG term). The difference is most visible in the sky around the sun disk in the IBL cubemap. | LOW | Cornette & Shanks 1992 "Physically Reasonable Analytic Expression for the Single-Scattering Phase Function" |
| `sky_cubemap_cs.hlsl` | Sun disk exclusion | Intentionally excludes the sun disk from the cubemap to avoid baking a point-source highlight. | Correct design decision. The sun should contribute via direct lighting, not IBL. No change needed. | — | Internal design |
| `height_fog_ps.hlsl` | `IntegrateExponentialFogRay` | Exact reference Frostbite Hillaire 2016 implementation including Taylor expansion at small falloff values. | This is a complete and correct reference implementation. | `height_fog_ps.hlsl` | Fog cutoff distance | `fogCutoffDistance` is declared in the CB but the code comment says "cutoff removed — fog always visible".

KEY FINDINGS
================================================================================

1. SCALAR PARAMETERS (Explicit, not hardcoded)
   ────────────────────────────────────────────────────────
   UE5 has NO predefined scalar parameters. Material authors define them in the
   shader graph. However, TYPICAL PBR materials expose:

   - Roughness        [0, 1]   (perceptual, remapped to α² in shader)
   - Metallic         [0, 1]   (dielectric ↔ metallic blend)
   - Specular         [0, 1]   (non-metallic specular strength)
   - Opacity          [0, 1]   (transparency, forward rendering only)
   - Normal Strength  [0, 2]   (normal map intensity)
   - AO Strength      [0, 1]   (ambient occlusion multiplier)
   - Emissive Intensity [0, ∞] (self-illumination HDR scale)
   - Displacement     [0, 1]   (parallax occlusion height)

2. VECTOR PARAMETERS (Explicit, not hardcoded)
   ────────────────────────────────────────────────────────
   - Base Color       RGB [0, 1]        (albedo tint)
   - Emissive Color   RGB [0, ∞]        (self-illumination color)
   - Subsurface Color RGB [0, 1]        (SSS transmission tint)
   - Tint Color       RGBA [0, 1]       (generic overlay)

3. TEXTURE PARAMETERS
   ────────────────────────────────────────────────────────
   STANDARD PBR INPUTS (material author defines which to use):

   - Base Color Texture       sRGB RGB8/BC1     → White (default)
   - Normal Map               Linear RGB8/BC1   → Flat (0, 0, 1) octahedral
   - Roughness Map            Linear R8/BC4     → 0.5 gray
   - Metallic Map             Linear R8/BC4     → 0.0 black
   - Ambient Occlusion Map    Linear R8/BC4     → 1.0 white
   - Emissive Map             HDR RGBA16F/BC6H  → (0, 0, 0, 0) black
   - Displacement / Height    Linear R8/BC4     → 0.5 gray

   DEFAULT TEXTURE VALUES (if null):
   ✓ BaseColor     → White (1, 1, 1, 1)     — reflects all light
   ✓ Normal        → Flat blue (0.5, 0.5, 1.0) — no perturbation
   ✓ Roughness     → 0.5 gray               — mid-tone
   ✓ Metallic      → 0.0 black              — fully dielectric (safe)
   ✓ AO            → 1.0 white              — no occlusion
   ✓ Emissive      → (0, 0, 0, 0) black     — no glow
   ✓ Displacement  → 0.5 gray               — no offset

4. UV TRANSFORMS
   ────────────────────────────────────────────────────────
   UE5: Per-texture-sampler in material graph
        TextureSample node includes ScaleX, ScaleY, OffsetX, OffsetY
        Each sampler has independent transform

   UzEngine (current): Only per-material in PerObjectCB

   Impact: Can't tile different textures at different scales
           (wood can be 2x tiling, normal at 1x tiling)

5. MATERIALINSTANCE STRUCTURE
   ────────────────────────────────────────────────────────
   INHERITANCE CHAIN (Max 5 levels):
   BasePBRMaterial (UMaterial)
   └── WoodMaterial (UMaterialInstance)
       └── OakWood (UMaterialInstance)
           └── WetOakWood (UMaterialInstance)

   SPARSE STORAGE (Only overrides):
   Each instance stores ONLY the parameters it overrides from parent.
   Parent's values are inherited (recursive lookup chain).

   Example memory:
   - BasePBRMaterial: 64 bytes (full struct)
   - WoodMaterial: 96 bytes (2 scalar overrides: Roughness, NormalStrength)
   - OakWood: 96 bytes (1 vector override: BaseColor)
   - WetOakWood: 96 bytes (1 scalar override: Roughness)

   Total for 3 variants: 256 bytes

   Comparison (fixed struct):
   - 4 × 48 bytes = 192 bytes (less memory, but can't extend)

6. GPU CONSTANT BUFFER LAYOUT
   ────────────────────────────────────────────────────────
   EXACT LAYOUT depends on material's shader graph. Example for typical PBR:

   [0:15]   float4 BaseColor           (albedo RGB + opacity A)
   [16:19]  float Metallic             (0 = dielectric, 1 = metal)
   [20:23]  float Roughness            (0 = mirror, 1 = diffuse)
   [24:27]  float Specular             (non-metal specular)
   [28:31]  float _Pad1                (alignment)
   [32:47]  float4 EmissiveColor       (RGB + intensity scale)
   [48:51]  float NormalStrength       (normal map intensity)
   [52:55]  float AOStrength           (AO multiplier)
   [56:59]  float DisplacementScale    (POM height)
   [60:63]  float _Pad2                (alignment)
   [64:79]  float4 UVScale             (TileX, TileY, OffsetX, OffsetY)
   [80:95]  [padding to 96 for GPU alignment]

   Total: 96 bytes (16-byte boundary)

7. FMATERIALRENDERPROXY PATTERN (CRITICAL)
   ────────────────────────────────────────────────────────
   Thread-safe snapshot system:

   GAME THREAD:
   - Material parameters can be modified at any time
   - At render time, call Material->GetRenderProxy()
   - Proxy captures parameter values THIS FRAME
   - Proxy is immutable after creation

   RENDER THREAD:
   - Receives immutable proxy for this frame
   - Reads parameters from proxy (NO virtual calls, direct map lookups)
   - Cannot modify proxy (no race condition)
   - Proxy is destroyed at end of frame

   This decouples game logic (modifying materials) from rendering
   (reading parameters for GPU upload).

ARCHITECTURAL PATTERNS TO ADAPT (Not Copy)
================================================================================

PATTERN 1: Virtual Material Interface
───────────────────────────────────────
Instead of:
  struct PBRMaterial { ... }  // Fixed fields

Do:
  class IMaterialInterface { virtual ... }  // Extensible
    └── class PBRMaterial : public IMaterialInterface
    └── class ClothMaterial : public IMaterialInterface
    └── class SkinMaterial : public IMaterialInterface

Benefits:
✓ Future shading models (cloth, hair, skin) without binary break
✓ Render code uses same interface for all material types
✓ Each subclass defines its own parameters

PATTERN 2: Sparse Parameter Overrides
──────────────────────────────────────
Instead of:
  struct Material {
    // 1000 instances = 1000 full struct copies = wasteful
  };

Do:
  class MaterialInstance {
    Parent* parent;
    Map<string, float> scalarOverrides;  // Only what differs
    // GetScalar() walks parent chain until found
  };

Benefits:
✓ Memory: 1000 instances with 2-3 overrides = 344 KB vs 48 KB
  Trade-off: Slightly more memory, but 10000× more flexibility
✓ Artist workflow: Create wood → oak → wet oak easily
✓ Inheritance: Don't duplicate shared parameters

PATTERN 3: Render-Time Proxy Snapshot
──────────────────────────────────────
Instead of:
  // Game thread modifies → Render thread reads (RACE!)
  drawCmd.material = gameThreadMaterial;

Do:
  // Game thread captures → Render thread reads immutable
  drawCmd.proxy = gameThreadMaterial->GetRenderProxy();  // SNAP!

Benefits:
✓ Thread-safe: No race condition between game & render threads
✓ Deterministic: Same parameters for entire frame
✓ Efficient: Single capture per material per frame

PATTERN 4: Parameter Metadata Registry
───────────────────────────────────────
Instead of:
  // Hardcoded offsets in constant buffer
  cbuffer Material { float roughness @ offset 20; ... }

Do:
  // Compile-time metadata
  Map<string, ParameterMetadata> {
    "Roughness" → {type: float, offset: 20, size: 4}
    "BaseColor" → {type: float4, offset: 0, size: 16}
    // Dynamically fill CB from proxy
  };

Benefits:
✓ Support unlimited parameters (not hardcoded)
✓ Extensible: New parameters = new metadata entry, no CB layout change
✓ Runtime flexibility: Can query parameter existence

MEMORY COMPARISON: Current vs Proposed
================================================================================

CURRENT (Fixed 48-byte struct):
  1 material instance = 48 bytes
  1000 instances      = 48 KB

PROPOSED Phase 2 (Sparse overrides):
  1 material instance with 3 scalar + 2 vector overrides:
    Base class overhead   = 64 bytes
    Pointers + metadata   = 40 bytes
    3 scalar params       = 120 bytes (40 × 3)
    2 vector params       = 112 bytes (56 × 2)
    1 texture param       = 40 bytes (only if overridden)
    ────────────────────────
    Total per instance    = 344 bytes (if overriding)
                          = 100 bytes (if inheriting all from parent)

  1000 instances with inheritance:
    - 10 base materials (parent)           = 64 × 10 = 640 bytes
    - 990 instances (mostly sparse)        = 100 × 990 = 99 KB
    ────────────────────────────
    Total                                  = ~99.6 KB

  Memory cost: 99.6 KB vs 48 KB = 2× for 10000× flexibility trade-off

PROFILING IMPACT:
  GetRenderProxy() overhead:  +0.2 ms per frame (acceptable, once per frame)
  Parameter lookup overhead:  +0.05 ms per frame (map lookups)
  Total added per frame:      +0.25 ms (negligible on modern hardware)

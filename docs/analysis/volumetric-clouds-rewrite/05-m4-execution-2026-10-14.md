### Scale audit and remaining cause

`cloud_shadow_cs.hlsl:35-65` clips the march to the cloud shell, the solid
planet and the map depth range, then removes the empty inner sphere.
The 50 km shadow distance sets cascade coverage; it is not accumulated as
50 km of cloud material. Near this scene's sun direction, the 3 km layer
contributes roughly 3 / 0.643 = 4.67 km of supported ray length.

At `:67-87`, stepLength = supportLength / steps and each contribution is
density * extinction * DENSITY_SCALE * stepLength. Extinction is km^-1
(`volumetric_clouds_component.h:97-101`), distances are km, and density
normalization matches the existing cloud LightMarch at
`cloud_raymarch_cs.hlsl:428-450`. There is no missing step-size factor or
km/m conversion demonstrated by this audit. Dividing by step count again
would make opacity depend incorrectly on the selected sample count.

The issue is the shared density/coverage signal: at coverage 0.45,
every sampled sun column through the 3 km layer contains cloud extinction.
`SampleDensity` uses a nonlinear remap of 3D shape noise plus erosion;
there is no independent 2D column-coverage field in that function. Coarse
noise filtering was tested as a possible cause of lost clear gaps, but
using base mip 0 increased the median optical depth and still produced
no clear columns. That unsuccessful experiment was reverted.

A uniform scale reduction cannot create the missing clear-sky samples.
Multiplying the original depth by 0.5 gives transmittance only
0.0552-0.2294 across the measured ground: moderate shadow, but nowhere
clear/lit. A factor of 0.1 gives 0.5603-0.7450: a relatively uniform
gray attenuation, matching the earlier thin-density diagnostic.
Subtracting a chosen optical-depth floor to manufacture clear patches
would no longer be Beer-Lambert integration of the shared cloud density.

The remaining work is shared density/coverage calibration or a patchy
column-coverage field, followed by silhouette and motion acceptance.
This bounded attempt stops here rather than changing the established
cloud material or shipping an arbitrary BSM-only optical-depth scale.
The feature remains OFF by default.

## Implementation

`r.Clouds.TemporalUpscale` defaults to false (`cloud_pass.cpp:48`).
Off selects the existing half-resolution output and M2 raymarch pipeline.
On selects a separately compiled Bayer raymarch, a quarter-resolution R32F
cloud-distance target, and two full-resolution RGBA16F histories. Changing
the mode retires the old textures after a one-time device-idle synchronization;
there is no per-frame idle wait.

The original `cloud_raymarch_cs.hlsl` and `cloud_composite_ps.hlsl` are
preserved exactly. The opt-in shader is separate because adding a runtime
branch to the default raymarch initially changed a few screenshot values
by one code value. A subsequent preprocessor-only variant reduced, but did
not eliminate, those differences. Exact default source preservation is
therefore part of the implementation, rather than treating high finite
PSNR as bit identity.

| Item | Implementation |
| --- | --- |
| 3.1 | `cloud_pass.cpp:212-228`: divisor 4 only when the CVar is enabled; divisor 2 otherwise. |
| 3.2 | `cloud_bayer.hlsli:3-23`: 4x4 ordered matrix and inverse slot selection; `cloud_raymarch_upscale_cs.hlsl:153` maps each quarter texel to one full-resolution pixel of the current sixteen-frame slot. |
| 3.3 | `cloud_temporal_cs.hlsl:54-82`: dispatch at full resolution; current-slot pixels pass through without blending, while other pixels reconstruct a cloud point and reproject history. First frame and invalid/off-screen history use current spatial samples. |
| 3.4 | `cloud_temporal_cs.hlsl:110-137`: dense 3x3 current quarter-grid neighborhood, YCoCg mean/variance, gamma 1.25, AABB color clipping and transmittance clipping. No sparse zero-filled Bayer samples enter the statistics. |
| 3.5 | `cloud_temporal_cs.hlsl:84-105`: 3x3 reversed-Z closest-fragment search and pixel-space GBuffer velocity divided by render size. Clear sky uses cloud-depth matrix reprojection instead of nonexistent geometry motion. The authorized SRV/resource assignments are `frame_atmosphere_passes.cpp:266-267`. |
| 3.6 | `cloud_raymarch_upscale_cs.hlsl:589,608`: accumulates `T * (1 - Tstep) * distance`, normalizes by total opacity and writes kilometers to R32F. Every ray starts with zero depth, including no-hit/depth-occluded rays. |
| 3.7 | `cloud_pass.cpp:739-787`: tracked current/front-depth reads, alternating history reads/writes and composite consumption of the written full-resolution history. Uninitialized history is neither sampled nor declared as a read. Frame gaps invalidate it. |

Both CB allocations remain 512 bytes, with C++ size/offset assertions.
Root constants remain twelve DWORDs. The primary march retains its counted
256-iteration cap, M1 adaptive stepping/STBN/mip filtering, and M2 lighting.
The default composite is unchanged; with the CVar on it samples the resolved
full-resolution texture at the existing fullscreen pixel centers.

## Motion, convergence and TAA

The checked-in `m3-motion.{lua,uzscene,uzproject}` fixture runs at 1280x720:
hold, 32-degree orbit plus 640-meter translation, hold, camera cut back,
then recovery. Lua logs record the actual camera changes; the checks are
not static-camera captures presented as motion.

The final moving-camera capture has no visible cloud trails or
smearing in frames 36/68, or a persistent cloud imprint after the cut at
116. Screenshots 117/124/132/145 show stable recovery. Evidence is
`.screenshots/cloud-m3/motion-{off,on}/motion/frames/` and
`motion-comparison.jpg`; measurements are in `motion-metrics.json`.
Mean moving sky difference versus off is 0.33235 display code values.
Comparing on frames with off frames shifted by -2/-1/0/+1/+2 gives
0.56859/0.41549/0.33247/0.41467/0.56849: the best match is the same frame,
not a lagged frame. After the cut, differences remain around the ordinary
0.35-code spatial reconstruction difference rather than producing a spike
or prolonged trail.

During the stationary post-motion hold, sky code-value CoV p95 is
0.001891 off and 0.002080 on (1.10x). At the static sun pose it is
0.001825 off and 0.001970 on (1.079x). Both are below the 1.2x gate.
These are 8-bit screenshot measurements on the specified low-contrast,
overcast reference, not an HDR transport proof or a claim about every
wind speed, sharp cloud silhouette, or camera-cut angle.

Clouds still composite before engine TAA. Current-slot samples are not
cloud-blended; the resolve fills every pixel and clips history before
TAA receives the image. The tested motion does not show a double-filter
ghosting failure, but the CVar remains off by default as required.

Final moving-camera GBV completed in approximately 132.6 seconds, under
the 175-second limit, with 154 rendered frames, zero tracked-state
claim disagreements and zero double imports. There are no cloud errors,
shader compilation failures, device removals or hangs. The eight existing
debug id 1422 initialization errors remain: six SkyCubemap subresources and
two GBuffer_Velocity allocations. Global zero-error GBV is not claimed.
Evidence: `.screenshots/cloud-m3/motion-gbv/motion/{run.log,manifest.json}`.

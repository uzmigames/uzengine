# M5 multi-layer density (2026-10-15)

## Implementation

The component accepts an optional `layers` array containing one to four
layers. Existing scenes omit it and retain their original single-shell
geometry. An explicitly authored neutral single layer also selects the
original density and march path. `r.Cloud.ProceduralNoise` remains true.

Each layer has a weather channel, altitude and height in km, density scale,
shape/detail amounts, weather exponent, shape bias, and four density-profile
coefficients. The profile is `exp * exp(exp_exponent * h) + linear * h +
constant`, multiplied into the height gradient. The default coefficients
produce exactly one. The global cloud type preserves the old gradient at
0.5; zero concentrates the profile near its base and one keeps a tall body.

`weather_texture_path` resolves through the project VFS, then the existing
engine/cwd cloud-asset lookup. Images decode to linear RGBA8, without sRGB
conversion; all four channels, including alpha, are coverage multipliers.
An empty path means uniform RGBA=(1,1,1,1), with no texture allocation.
The sample scenes use the existing `textures/checker.png`: red modulates
the low layer and alpha controls the high layer.

The explicit-layer view march computes four shell intervals once, jumps
directly across gaps, and keeps one counted 256-iteration budget shared
across all layers. Overlaps accumulate density. STBN jitter, adaptive
stepping, mip footprints and early termination remain. Beer-shadow
generation also integrates explicit layers with a shared bounded budget.

CloudCB grows from 512 to 1024 bytes. Three float4[4] arrays start at
368/432/496; count/weather descriptor/path flag are at 348/352/356.
This reuses the existing per-frame CB ring instead of introducing another
bindless resource and lifetime. Root constants remain 12 DWORDs, and no
global root-signature or sampler register changes were made. Weather uses
the existing s3 sampler; BSM still uses s2.

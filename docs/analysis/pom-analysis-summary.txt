KEY FINDINGS
============

1. MATERIAL EXPRESSION COMPOSITION PATTERN
   - UE5 uses virtual dispatch per expression type (BumpOffset, Normal, etc.)
   - Each expression compiles to shader code via FMaterialCompiler::Compile()
   - No switch-on-type; no union types; no RTTI
   - Pattern: subclass UMaterialExpression, override Compile(), return code index

   File: W:\UE_5.6_Source\Engine\Source\Runtime\Engine\Public\Materials\MaterialExpressionBumpOffset.h
   File: W:\UE_5.6_Source\Engine\Source\Runtime\Engine\Private\Materials\MaterialExpressions.cpp

2. MATERIAL PROPERTIES AS FIRST-CLASS ENUM
   - UE5 defines EMaterialProperty with 32+ values: MP_EmissiveColor, MP_Normal, MP_Metallic, etc.
   - MP_Displacement is **distinct** from MP_WorldPositionOffset and MP_PixelDepthOffset
   - Allows variant shaders per property (only include code for connected properties)

   File: W:\UE_5.6_Source\Engine\Source\Runtime\Engine\Public\SceneTypes.h (lines 143-187)

3. SHADER CODE GENERATION VIA INTERMEDIATE REPRESENTATION
   - FShaderCodeChunk structure maintains HLSL code + type + derivatives
   - Two variants: DefinitionFinite (LOD) and DefinitionAnalytic (chain rule)
   - Expression compilation builds AST of code chunks; final pass generates shader
   - Enables dead-code elimination and constant folding

   File: W:\UE_5.6_Source\Engine\Source\Runtime\Engine\Private\Materials\HLSLMaterialTranslator.h (lines 82-170)

4. COORDINATE SPACE TRANSFORMATIONS
   - BumpOffset transforms camera vector from World → Tangent space at compile-time
   - Formula: OutputUV = InputUV + (CameraVec.xy in tangent space) * (Height - RefPlane) * Ratio
   - No runtime matrix inverse; all computed in HLSL as matrix multiplication
   - Supports multiple texture coordinate sources via optional inputs

   Compile code: W:\UE_5.6_Source\Engine\Source\Runtime\Engine\Private\Materials\MaterialExpressions.cpp

5. DISPLACEMENT HIERARCHY IN UE5
   - Vertex-space: MP_WorldPositionOffset (pre-rasterization, geometric)
   - Pixel-space: BumpOffset (parallax texture offset, per-fragment)
   - Depth-space: MP_PixelDepthOffset (post-projection depth tweak)
   - Nanite-space: MP_Displacement (for GPU-driven geometry, Nanite virtual mesh)
   - Screen-space ray marching: Custom shaders (8-32 step iterations)

6. QUALITY TIER ARCHITECTURE
   - No single "POM shader"; instead precompile variants with different PARALLAX_STEPS
   - Preprocessor defines: PARALLAX_STEPS = 8/16/32 based on EMaterialQualityLevel
   - Distance-based LOD: reduce steps at >50m for performance
   - UE5 approach: zero runtime branching; compile multiple shader variants

7. ANTI-PATTERNS TO AVOID
   - No switch-on-material-type in shader (bloats code, unfair to profile)
   - No per-pixel function pointers (GPU ISAs don't support)
   - No unbounded loops (must be statically determinable loop count)
   - No runtime dispatch of displacement algorithm (compile-time only)

ARCHITECTURAL PRINCIPLES EXTRACTED
====================================

Principle 1: EXPRESSION-BASED COMPOSITION
  - Each material feature (parallax, normal, metallic) is independent expression
  - Expressions compose via function call graph; no global switch/dispatch
  - Benefit: modular, testable, extensible without shader bloat

Principle 2: LAZY COMPILATION
  - Shader only includes code for **connected** properties
  - Optional inputs checked at compile-time (e.g., HeightRatioInput)
  - Benefit: minimal shader size; no unused shader code

Principle 3: PROPERTY SEMANTICS MATTER
  - Displacement (geometric), parallax (texture offset), and depth (post-proj) are **different**
  - Each requires different coordinate space, evaluation pipeline, and integration point
  - Benefit: correctness; prevents mixing up concepts; enables future GPU-driven rendering

Principle 4: DERIVATIVES ARE FIRST-CLASS
  - Shader code generation tracks both finite differences (for LOD) and analytic derivatives (for precision)
  - Necessary for correct texture sampling and future screen-space derivative work
  - Benefit: robust LOD calculation; basis for TAA, motion blur, gradient-based effects

Principle 5: VARIANTS OVER BRANCHING
  - Quality tiers (Low/Med/High) compiled as separate shader variants, not runtime branches
  - Each platform/quality level gets dedicated shader code
  - Benefit: cache-friendly; predictable GPU performance; no stalls from branch divergence

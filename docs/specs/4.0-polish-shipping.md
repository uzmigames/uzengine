# Spec 4.0 — Polish & Shipping

> **Goal**: Platform SDKs, networking, optimization (GPU-driven rendering, Nanite-style geometry, Lumen GI, hardware RT), and release.

## 4.0 — Platform SDKs

### How the Big Engines Solve This

| Engine | Approach | Details |
|--------|----------|---------|
| **Unreal 5.6** | `FOnlineSubsystem` | Abstract interface per platform. Plugins: `OnlineSubsystemSteam`, `OnlineSubsystemEOS`, `OnlineSubsystemNull`. `IOnlineIdentity`, `IOnlineAchievements`, `IOnlineLeaderboards`. Async delegates for all operations. Platform-specific SDKs in NDA modules (Sony, Xbox). |
| **Godot 4.x** | Minimal built-in | No built-in platform abstraction. Community plugins for Steam (GodotSteam), no official EOS/console support. Android: `GodotPlayGameServices`. Export templates handle platform differences. |
| **Unity 6** | `Social` API + packages | Basic `Social` API for leaderboards/achievements. Steam via Steamworks.NET (third-party). EOS via Epic's C# wrapper. Google Play via Unity Gaming Services. Console SDKs (NDA, private packages). Relatively fragmented — many third-party solutions. |

**UzEngine**: `IPlatformServices` unified interface. Per-platform backends (Steam, Epic, Google, Sony, Xbox). Async by default (all network operations). Graceful degradation (unavailable service → no-op). NDA-safe: console SDKs in separate private repos.

## 4.1 — Networking

### How the Big Engines Solve This

| Engine | Approach | Details |
|--------|----------|---------|
| **Unreal 5.6** | Built-in replication | Authoritative server model. `UPROPERTY(Replicated)` for property sync. `UFUNCTION(Server/Client/NetMulticast)` for RPCs. Relevancy system (distance, area, custom). Delta compression + bitpacking. Replay system (`FNetworkDemoDriver`). Dedicated server via `BuildCookRun` with `-server`. |
| **Godot 4.x** | `MultiplayerPeer` + `SceneReplicator` | `ENetMultiplayerPeer` for networking. `MultiplayerSpawner` / `MultiplayerSynchronizer` for automatic sync. RPC via `@rpc` annotations. Simpler than Unreal — less control over relevancy and delta compression. |
| **Unity 6** | Netcode for GameObjects / DOTS | `NetworkBehaviour` for replicated components. `NetworkVariable<T>` for synced properties. `[ServerRpc]`/`[ClientRpc]` attributes. Relay (Unity Gaming Services) for NAT traversal. No built-in relevancy system (developer implements). Dedicated server via headless build. |

**UzEngine**: Unreal-style authoritative server with property replication. `REPLICATE(property, condition)` macro. RPCs: `SERVER_RPC`, `CLIENT_RPC`, `MULTICAST_RPC`. Relevancy (distance, area, custom rules). Delta compression with bitpacking. Dedicated server (`--headless --server`). Listen server. Replay system for debugging and game replays. ENet for reliable UDP transport.

## 4.2 — Optimization

### How the Big Engines Solve This

| Feature | Unreal 5.6 | Godot 4.x | Unity 6 |
|---------|-----------|-----------|---------|
| **GPU-driven rendering** | Nanite: virtual geometry, GPU-driven culling/rasterization, unlimited triangles. Multi-draw-indirect for non-Nanite meshes. | Basic GPU frustum culling. No GPU-driven draw submission. Manual LOD. | SRP Batcher (batches draw calls). Hybrid Renderer (DOTS) for GPU instancing. No Nanite equivalent. |
| **Virtual geometry** | Nanite — DAG of mesh clusters, software rasterizer for small triangles, hardware for large. LOD-free. | None. | None (Unity 6 announced Adaptive Probe Volumes but no virtual geometry). |
| **Global illumination** | Lumen — screen-space traces + surface cache (meshSDF) + radiance cache. Hardware RT acceleration path. Real-time, fully dynamic. | SDFGI (signed distance field GI) + SSIL (screen-space indirect light). Baked lightmaps (LightmapGI). VoxelGI. | Screen-space GI (SSGI in HDRP). Adaptive Probe Volumes. Baked lightmaps. No equivalent to Lumen. |
| **Hardware RT** | Full DXR: RT reflections, RT shadows, RT AO, RT GI (Lumen acceleration), path tracing mode. | Not available (under discussion). | DXR: RT reflections, RT AO in HDRP. Path tracing mode. |

**UzEngine approach**:

**GPU-driven rendering**: Multi-draw-indirect for all opaque geometry. GPU frustum + occlusion culling (hierarchical Z-buffer). Draw call count independent of object count. This is the foundation — even without Nanite-style virtual geometry, GPU-driven rendering is a massive win.

**Nanite-style virtual geometry** (stretch goal): Mesh cluster DAG, GPU-driven LOD selection, software rasterizer for small triangles. This is the most complex rendering feature in any engine. Study UE5 approach, implement simplified version.

**Lumen-style GI**: Software ray-traced GI — screen-space traces + surface cache (mesh SDFs) + radiance cache. Hardware RT acceleration path for RTX/RDNA2+ GPUs. This gives dynamic, fully real-time global illumination without baked lightmaps.

**Hardware RT**: DXR reflections, RT shadows, RT AO, RT GI (Lumen acceleration), path tracing reference mode.

**Path tracing**: Full path tracer for reference rendering and cinematics. Not real-time — convergence-based, used for visual validation and high-quality offline renders.

## 4.3 — Release

### How the Big Engines Solve This

| Engine | Distribution | CI/CD | Documentation |
|--------|-------------|-------|---------------|
| **Unreal** | Epic Games Launcher + GitHub source | Horde (custom build system). BuildGraph for CI. Automated testing via Gauntlet. | Extensive docs.unrealengine.com. Learning portal. |
| **Godot** | godotengine.org + GitHub releases | GitHub Actions. SCons build matrix. Automated export template builds. | docs.godotengine.org. Community tutorials. |
| **Unity** | Unity Hub installer + Asset Store | Internal CI (Katana). Package validation. Automated regression tests. | docs.unity3d.com. Unity Learn. |

**UzEngine**:
- **VS Marketplace** — extension published and installable
- **CI/CD** — GitHub Actions: build matrix (MSVC/Clang/Zig × Windows/Linux), tests, screenshot regression, package
- **Documentation** — API docs, tutorials, example projects (FPS template, third-person template)
- **Benchmark suite** — standard scenes with FPS/memory/draw call tracking over time
- **Screenshot regression** — automated render comparison vs golden images, flag visual regressions
- **License** — engine license + all third-party licenses documented and compatible

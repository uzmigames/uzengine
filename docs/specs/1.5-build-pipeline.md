# Spec 1.5 (Build) — Build Pipeline & Packager

> **Goal**: Shader compiler, asset processor, and game packager — compile and package a game project into a self-contained executable.

---

## How the Big Engines Solve This

### Unreal Engine 5.6

**Shader compilation**: DXC (HLSL → DXIL/SPIR-V), custom shader compiler pipeline. **Shader permutation explosion** is a major problem — Unreal generates tens of thousands of shader variants from feature flags, quality levels, and platform settings. Distributed shader compilation (`ShaderCompileWorker`) across multiple cores. Shader cache (`DerivedDataCache`) keyed by content hash — skips recompilation. Runtime shader compilation disabled in shipping builds.

**Asset processing**: `UnrealPak` for asset packing. `CookContent` command processes all assets: textures compressed to platform-specific formats (BC7, ASTC, ETC2), meshes optimized, audio encoded. Content-addressable storage in DDC. Incremental cooking — only changed assets reprocessed. Asset dependency graph tracks what needs recooking when a source changes.

**Packaging**: `BuildCookRun` — builds C++ code, cooks assets, packages into `.pak` files, generates platform executable. Per-platform output: Windows `.exe` + `.pak`, Android `.apk`, iOS `.ipa`. Editor-only code (`WITH_EDITOR` guards) stripped from shipping builds. ~30-60 minute full cook for large projects.

### Godot 4.x

**Shader compilation**: GLSL/Vulkan SPIR-V compiled at runtime or cached. No offline permutation compilation. Shader cache per driver version. Simpler than Unreal — fewer permutations, but slower first-launch experience.

**Asset processing**: `.import` sidecar files define import settings. Textures compressed on import (VRAM Compressed → BPTC/S3TC/ETC2). Meshes not significantly optimized (no LOD generation built-in). `ResourceFormatLoader` handles format-specific loading.

**Packaging**: Export templates — precompiled engine binary + user scripts + assets. `.pck` archive (custom format). `EditorExportPlatform` per target. Size stripping (`--strip-debug`). Android: Gradle-based APK generation. Web: Emscripten build.

### Unity 6

**Shader compilation**: `ShaderCompiler` — HLSL → platform-specific (DXBC, SPIR-V, MSL, GLSL). Shader variant stripping in build settings. `ShaderVariantCollection` for prewarming. Shader keyword system for permutations. Build-time compilation with async shader loading at runtime.

**Asset processing**: AssetBundle system → Addressables. Texture compression per build target. Sprite atlas generation. Mesh optimization (unity-generated LODs). Asset dependency tracking via GUID. `BuildPipeline` API for custom build scripts.

**Packaging**: `BuildPipeline.BuildPlayer()`. IL2CPP converts C# → C++ → native. Platform SDKs (Android NDK, Xcode). Incremental builds for C++ (IL2CPP). Asset bundles for DLC/streaming. App Bundle (Android) for size optimization.

---

## The Problem

The build pipeline is the bridge between the editor (human-friendly formats) and the player (optimized runtime formats). It must:

1. **Compile shaders fast** — permutation explosion can generate thousands of variants; caching and parallelism are essential
2. **Process assets per-platform** — BC7 for Windows, ASTC for mobile, etc.
3. **Be incremental** — only reprocess changed assets; full rebuilds are unacceptable for iteration
4. **Produce self-contained output** — single executable + asset packs, no engine installation required
5. **Strip editor code** — debug/editor features must not ship in game builds

Unreal does this best but is incredibly slow (30-60 min full cook). Godot is fast but limited (no LOD generation, no permutation management). Unity is middle-ground but IL2CPP compilation is slow.

**Our advantage**: We design the asset formats from scratch — `.uz*` JSON → binary cooking is straightforward.

## UzEngine Approach

### 1.5.0-SC — Shader Compiler

**DXC integration**: HLSL → DXIL (DX12), HLSL → SPIR-V (Vulkan). **SPIRV-Cross**: SPIR-V → MSL (Metal), SPIR-V → GLSL (fallback).

**Permutation system**: Feature flags as `#define` macros → generate all valid combinations at build time. Permutation key = sorted flag set hash → cache lookup.

```
// Shader source declares permutations:
#pragma uz_permutation HAS_NORMAL_MAP
#pragma uz_permutation HAS_EMISSIVE
#pragma uz_permutation SHADOW_QUALITY (LOW, MEDIUM, HIGH)

// Build generates: 2 × 2 × 3 = 12 variants
```

**Shader cache**: Content hash (source + includes + defines) → skip recompilation if hash matches cached bytecode. Cache stored in `cache/shaders/`.

**Reflection**: SPIRV-Reflect extracts binding layout → auto-generates root signature (DX12) or descriptor set layout (Vulkan). No manual binding specification.

**Runtime compilation** (dev only): File watcher on `shaders/` → recompile on save → hot-swap PSO. Disabled in shipping.

### 1.5.1-AP — Asset Processor

| Asset Type | Source | Processing | Output |
|------------|--------|-----------|--------|
| Textures | PNG, JPG, EXR, HDR | Compress to BC7 (Windows), ASTC (mobile), ETC2 (GLES) | Binary texture blob |
| Meshes | `.uzmesh` (JSON + binary) | meshoptimizer: vertex cache, overdraw reduction, LOD generation | Optimized binary mesh |
| Audio | WAV, OGG, MP3 | Encode to OGG/Opus per quality setting | Compressed audio |
| Materials | `.uzmaterial` (JSON) | Compile shader graph → HLSL → shader permutations | Compiled material |

**Asset dependency graph**: Changing a texture reprocesses dependent materials. Changing a shader graph recompiles all instances.

**Incremental processing**: Content hash per source file → only reprocess if hash changed. Dependency graph triggers cascading reprocessing.

### 1.5.2-PK — Packager

**`.uzpak` archive**: Pack all processed assets into archive files. Compressed with LZ4 (fast decompression at runtime). Asset manifest (JSON) maps logical paths to archive offsets.

**Scene baking**: Strip editor-only data (debug names, editor metadata). Resolve all asset references to archive offsets. Serialize to binary format (faster load than JSON).

**Executable generation**: Link runtime C++ (editor module stripped via `#ifdef UZ_EDITOR`). Embed or bundle asset packs. Output per-platform:

```
build/
├── win64/
│   ├── MyGame.exe          # Runtime + game DLL linked
│   └── data/
│       ├── assets.uzpak    # All processed assets
│       └── manifest.json   # Asset index
├── linux/
│   ├── MyGame              # ELF binary
│   └── data/
└── android/
    └── MyGame.apk          # NDK build + assets
```

**Config stripping**: Remove dev-only config values, bake shipping settings. No debug overhead in release.

## Deliverables

### Shader Compiler
| Task | Acceptance Criteria |
|------|-------------------|
| DXC integration | HLSL compiles to DXIL (DX12) and SPIR-V (Vulkan) |
| SPIRV-Cross | Cross-compiled shaders valid for Metal/GLSL |
| Permutation system | N variants generated from 1 shader with feature flags |
| Shader cache | Second build skips unchanged shaders |
| Reflection | Root signature auto-extracted, no manual binding |
| Runtime compilation | Edit shader → auto-recompile → viewport updates |

### Asset Processor
| Task | Acceptance Criteria |
|------|-------------------|
| Texture compression | Textures compress per target platform |
| Mesh optimization | meshoptimizer reduces draw call count and vertex cache misses |
| Audio encoding | Audio files compressed, play correctly |
| Dependency graph | Changing texture reprocesses dependent materials |
| Incremental processing | Second build processes only modified assets |

### Packager
| Task | Acceptance Criteria |
|------|-------------------|
| `.uzpak` archive | Assets load from archive at runtime |
| Scene baking | Baked scene loads faster than JSON |
| Executable generation | Self-contained .exe runs game without engine |
| Windows packaging | Game runs on machine without engine installed |
| Config stripping | Shipping build has no debug overhead |

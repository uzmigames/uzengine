# Spec 3.0 — MCP Integration

> **Goal**: MCP server exposing engine manipulation tools to LLMs (Claude, GPT, etc.), AI tool integration for content generation, and end-to-end AI content pipeline.

---

## How the Big Engines Solve This (AI/Automation)

### Unreal Engine 5.6

**Editor scripting**: Python scripting (`unreal` module) for editor automation. Blueprint scripting for gameplay. `UEditorUtilityWidget` for custom editor tools. No LLM integration built-in — third-party plugins (e.g., GPT plugins) provide basic integration.

**Content generation**: No built-in AI content generation. Procedural content generation via C++/Blueprint (PCG framework). MetaHuman for character creation (not AI-generated). Quixel Megascans library for assets.

**Automation**: `UAutomationTest` for automated testing. `FAutomationTestBase` runs in headless mode. Screenshot comparison tests. Command-line automation via `UnrealEditor-Cmd.exe`.

**Limitation**: Unreal has no structured API for external AI agents to manipulate the engine. Python scripting exists but isn't designed for LLM consumption (complex API, no schema descriptions).

### Godot 4.x

**Editor scripting**: GDScript/C# for editor plugins (`@tool` scripts). `EditorPlugin` API for custom UI and tools. `EditorScript` for one-off automation.

**Content generation**: No built-in AI. Community plugins for Stable Diffusion texture generation. No structured LLM integration.

**Automation**: `--headless --script` for CLI automation. Scene loading and screenshot capture possible via script. No MCP or LSP-style structured tool API.

### Unity 6

**Editor scripting**: C# `MenuItem` / `EditorWindow` for custom tools. `AssetPostprocessor` for import hooks. `BuildPipeline` for automated builds. Unity Muse (AI assistant) for code generation, sprite generation, texture creation — first built-in AI integration in a major engine.

**Unity Muse**: Chat-based interface inside the editor. Generates C# scripts, sprites, textures. Uses Unity's own AI models. Limited to Unity ecosystem.

**Limitation**: Unity Muse is a closed system — you can't plug in your own AI providers or define custom tools. It's an AI assistant inside Unity, not an AI integration framework.

---

## The Problem

None of the big engines have a **structured, provider-agnostic API for external AI agents to manipulate the engine**. They all bolt on AI features as internal tools, not as an integration layer.

UzEngine's key differentiator is being **AI-first**:

1. **MCP protocol** — standard protocol for LLM tool use, supported by Claude, ChatGPT, and others
2. **Provider-agnostic** — swap AI providers via config, no code changes
3. **Open formats** — JSON everywhere means LLMs can read/write any asset without specialized tooling
4. **Visual feedback loop** — `--screenshot` lets LLMs see render results and iterate
5. **Semantic metadata** — every parameter in every format has description, range, and units

## UzEngine Approach

### 3.0 — MCP Server

Node.js server implementing the MCP protocol (stdio/SSE transport). Exposes structured tools that LLMs can discover and invoke.

**Scene tools**:
```json
{
  "name": "create_entity",
  "description": "Create a new entity in the scene with specified components",
  "parameters": {
    "name": "string",
    "components": {
      "transform": { "position": "[x,y,z]", "rotation": "[x,y,z]" },
      "mesh": { "asset": "content path to .uzmesh" },
      "light": { "type": "point|directional|spot", "color": "[r,g,b]", "intensity": "float" }
    },
    "parent": "optional entity name"
  }
}
```

**Query tools**: `get_scene_tree`, `get_entity_components`, `get_logs`, `get_stats`.
**Asset tools**: `import_asset`, `modify_material`, `create_vfx`.
**Screenshot tool**: `capture_screenshot` → render frame → return PNG image for LLM vision.

### 3.1 — AI Tool Integration

**Provider abstraction**: `ai::Generate(category, prompt)` routes to configured provider.

```json
{
  "ai_providers": {
    "texture": { "primary": "nano-banana", "fallback": "flux-1.1-pro" },
    "3d_model": { "primary": "meshy-6", "fallback": "tripo" },
    "voice": { "primary": "elevenlabs" },
    "music": { "primary": "aiva" },
    "sfx": { "primary": "elevenlabs-sfx" },
    "animation": { "primary": "deepmotion" }
  }
}
```

Each provider has a standard interface: `generate(prompt, options) → asset file`. Result is auto-imported into the project via the asset pipeline.

### 3.2 — AI Content Pipeline

End-to-end generation from text prompt to playable content:

```
"Create a fire spell explosion VFX"
  1. Generate fire_particle texture → Nano Banana → .png imported
  2. Generate spark mesh → Meshy → .fbx → imported + split
  3. Generate fire crackling SFX → ElevenLabs → .wav imported
  4. LLM writes fire_explosion.uzmaterial (JSON)
  5. LLM writes fire_explosion.uzvfx (JSON)
  6. Runtime loads VFX → --screenshot → LLM reviews
  7. LLM iterates (adjust colors, timing, particle count)
  8. Done — zero manual work
```

**Visual iteration**: Screenshot → LLM vision → feedback → auto-adjust parameters. Loop until LLM is satisfied with the visual result.

**Schema validation feedback**: Invalid JSON → error message → LLM auto-corrects. Self-healing asset generation.

# Spec 1.2 — RHI (Rendering Hardware Interface)

> **Goal**: Abstract GPU interface with four complete backends (DX12, DX11, Vulkan, Metal) — device creation, command recording, resource management, pipeline state, shader loading, descriptor management, profiling, and debug validation.

---

## How the Big Engines Solve This

### Unreal Engine 5.6

**Architecture**: `FDynamicRHI` abstract interface with backend implementations (`FD3D12DynamicRHI`, `FVulkanDynamicRHI`, `FMetalDynamicRHI`). The RHI runs on a dedicated **RHI thread** — commands are recorded on the render thread, submitted on the RHI thread, executed on the GPU. Triple-buffered command lists.

**Resource management**: `FRHIResource` base class with reference counting. `D3D12MemoryAllocator` (AMD) for GPU memory. Transient resource system — per-frame resources allocated from a pool and aliased. Placed resources for explicit memory control. Streaming manager for LOD textures.

**Descriptors (DX12)**: SM6.6 bindless model — `ResourceDescriptorHeap[]` and `SamplerDescriptorHeap[]` accessed by index in shaders. No manual root signature binding for resources. Descriptor heap is one global heap per type. This eliminated the old per-draw-call descriptor table pattern.

**Pipeline state**: `FGraphicsPipelineState` cached by hash. PSO compilation is async — game uses a default PSO while the target PSO compiles in background. PSO cache serialized to disk between runs (eliminates shader stutter on second launch).

**Shader loading**: `FShaderResource` loaded from cooked `.ushaderbytecode` files. Reflection via SPIRV-Reflect (even for DX12 — all shaders go through SPIR-V intermediate). Root signature auto-generated from reflection data — no manual binding specification.

**GPU profiling**: `FD3D12GPUProfiler` — triple-buffered timestamp queries. `SCOPED_GPU_TIMER(name)` macro. Results flow to Unreal Insights for timeline visualization.

**GPU crash debugging**: `DRED` (Device Removed Extended Data) enabled in dev builds. GPU breadcrumbs via `ID3D12GraphicsCommandList::WriteBufferImmediate()` — on TDR, last breadcrumb shows which command caused the hang.

### Godot 4.x

**Architecture**: `RenderingDevice` abstract class (introduced in 4.0 for Vulkan). Backends: `RenderingDeviceDriverVulkan`, `RenderingDeviceDriverD3D12` (added 4.3+), `RenderingDeviceDriverMetal` (added 4.4+). Significantly simpler than Unreal — fewer abstraction layers, more direct API mapping.

**Resource management**: `RID` (Resource ID) — generational handle system. `RID_Owner<T>` manages typed resource pools. GPU memory via VMA (Vulkan Memory Allocator) or D3D12MA. No transient resource aliasing — simpler but wastes memory for per-frame resources.

**Descriptors**: Vulkan descriptor sets with pre-baked layouts. DX12 backend uses descriptor heaps but not full bindless (SM5 level). No SM6.6 bindless support yet.

**Pipeline state**: `RDD::PipelineID` cached. No async PSO compilation — can cause hitches on first use of a new material. Pipeline cache serialized per driver version.

**Shader loading**: Custom `GDShader` format. Offline compilation in editor, runtime loads pre-compiled blobs. Reflection embedded in shader metadata.

**GPU profiling**: `RenderingDevice::capture_timestamp()` — basic timestamp queries. Results exposed to editor profiler. No breadcrumb system.

### Unity 6

**Architecture**: `CommandBuffer` API — game records commands, Unity batches and submits. Backends: DX11, DX12, Vulkan, Metal, OpenGL. **SRP (Scriptable Render Pipeline)** lets users define the entire rendering flow in C# — `RenderGraph` API for resource-managed frame graphs.

**Resource management**: `GraphicsBuffer`, `RenderTexture`, `ComputeBuffer`. Automatic memory management via C# GC for metadata, manual for GPU resources. `AsyncGPUReadback` for CPU readback without stalls.

**Descriptors**: Abstracted away entirely — user binds resources by name (`material.SetTexture("_MainTex", tex)`). Backend handles descriptor allocation. No direct bindless access in user code (Unity abstracts this).

**Pipeline state**: Handled internally by SRP. `Material` + `Shader` + render state = PSO. Shader warmup API for pre-compilation. Shader variant stripping in build.

**GPU profiling**: `CommandBuffer.BeginSample/EndSample`. Frame Debugger in editor. RenderDoc integration. Custom profiler markers.

## The Problem

The RHI is the most critical abstraction in the engine — every pixel on screen goes through it. It must:

1. **Hide API differences** — DX12, DX11, Vulkan, Metal have fundamentally different resource binding models, synchronization, and memory management
2. **Expose modern features** — SM6.6 bindless, mesh shaders, ray tracing must not be lowest-common-denominator
3. **Minimize CPU overhead** — command recording must be lockless and parallelizable
4. **Manage GPU memory efficiently** — transient resources, aliasing, streaming, budget tracking
5. **Fail gracefully** — GPU crashes (TDR) must produce actionable diagnostics, not just "device lost"
6. **Support async compilation** — PSO stutter is unacceptable in a shipping game

Unreal's RHI is the gold standard but extremely complex (~200K lines across all backends). Godot's is cleaner but missing modern features (no bindless, no async PSO). Unity hides too much — users can't access low-level GPU features when needed.

**Our advantage**: The abstraction was designed for DX12 SM6.6 first, then DX11, Vulkan, and Metal were added without compromising the modern-API design. All four backends implement the same `IRHIDevice` / `IRHICommandList` interface — the renderer never sees backend-specific types.

## UzEngine Approach

### Core Abstractions

```cpp
// Device — GPU handle, feature queries, resource creation
class IRHIDevice {
    virtual RHIBufferHandle CreateBuffer(const BufferDesc& desc) = 0;
    virtual RHITextureHandle CreateTexture(const TextureDesc& desc) = 0;
    virtual RHIPipelineHandle CreateGraphicsPipeline(const GraphicsPipelineDesc& desc) = 0;
    virtual RHIPipelineHandle CreateComputePipeline(const ComputePipelineDesc& desc) = 0;
    virtual RHIShaderHandle CreateShader(const ShaderDesc& desc) = 0;
    virtual void DestroyBuffer(RHIBufferHandle handle) = 0;
    // ... feature queries, adapter info, memory budget
};

// Command List — recorded on render thread, submitted on RHI thread
class IRHICommandList {
    virtual void SetPipeline(RHIPipelineHandle pipeline) = 0;
    virtual void SetVertexBuffer(uint32_t slot, RHIBufferHandle buffer) = 0;
    virtual void SetIndexBuffer(RHIBufferHandle buffer, IndexFormat format) = 0;
    virtual void SetConstantBuffer(uint32_t slot, RHIBufferHandle buffer) = 0;
    virtual void DrawIndexed(uint32_t indexCount, uint32_t startIndex, int32_t baseVertex) = 0;
    virtual void Dispatch(uint32_t x, uint32_t y, uint32_t z) = 0;
    virtual void ResourceBarrier(RHITextureHandle tex, ResourceState before, ResourceState after) = 0;
    virtual void CopyBuffer(RHIBufferHandle dst, RHIBufferHandle src, uint64_t size) = 0;
    // ... clear, copy texture, resolve MSAA, etc.
};

// Swap Chain — present to window
class IRHISwapChain {
    virtual RHITextureHandle GetCurrentBackBuffer() = 0;
    virtual void Present(bool vsync) = 0;
    virtual void Resize(uint32_t width, uint32_t height) = 0;
};

// Fence — CPU/GPU synchronization
class IRHIFence {
    virtual void Signal(uint64_t value) = 0;
    virtual void WaitCPU(uint64_t value) = 0;
    virtual bool IsComplete(uint64_t value) = 0;
};
```

All resources are **handle-based** (`HandleMap<T>` from 1.1) — no raw pointers cross the RHI boundary. Generation counters prevent use-after-free.

### DX12 SM6.6 Backend

**Bindless descriptors**: One global `CBV_SRV_UAV` descriptor heap, one global sampler heap. Resources get a persistent descriptor index on creation. Shaders access via `ResourceDescriptorHeap[index]` — no per-draw descriptor table swaps.

```hlsl
// SM6.6 shader access
Texture2D tex = ResourceDescriptorHeap[textureIndex];
float4 color = tex.Sample(SamplerDescriptorHeap[samplerIndex], uv);
```

This eliminates the biggest DX12 CPU overhead (descriptor management) and matches how modern engines work post-SM6.6.

**Memory management**: D3D12MemoryAllocator (AMD GPUOpen) for suballocation. Three memory pools:
- **Default** heap — GPU-only (textures, vertex/index buffers)
- **Upload** heap — CPU-writable (constant buffers, staging)
- **Readback** heap — CPU-readable (screenshots, profiler data)

**Command recording**: Triple-buffered command allocators. Render thread records into `ID3D12GraphicsCommandList`. Frame N records while frame N-1 executes on GPU and frame N-2's fence is waited on for resource reclaim.

**Pipeline state**: PSO cache with content-hash lookup. Async compilation on worker thread — renderer uses a default wireframe PSO until target PSO is ready. Cache serialized to disk (`cache/pso/`).

**Shader loading**: DXC compiles HLSL → DXIL. SPIRV-Reflect extracts binding layout → auto-generates root signature. No manual binding specification needed. Shader hot-reload via file watcher in dev builds.

### DX11 Backend

**Target**: Windows with D3D11.1+ capable hardware. Activated via `--rhi dx11` or auto-detect fallback when DX12 is unavailable.

**Shader model**: SM5.0 / DXBC bytecode compiled by FXC. Bindless is not available — shaders use the Input Assembler path (`#ifdef UZ_BINDLESS` guards in dual-path HLSL).

**Memory management**: No explicit allocator — D3D11 manages GPU memory internally. The driver handles resource placement and hazard tracking automatically.

**Key design differences from DX12**:
- No descriptor heaps, no root signatures, no command queues
- Immediate context (`ID3D11DeviceContext1`) — command recording is single-threaded
- Dynamic constant buffers use `Map(D3D11_MAP_WRITE_DISCARD)` — write-combined memory, CPU reads back undefined data (common DX11 hazard)
- GPU profiler uses `ID3D11Query` with `D3D11_QUERY_TIMESTAMP` instead of DX12 timestamp heaps
- No DRED; GPU crash info limited to `DXGI_ERROR_DEVICE_REMOVED`

**Implementation**: `runtime/engine/rhi/dx11/` — 11 files (device, command list, swapchain, fence, GPU profiler, resources).

### Vulkan Backend

**Target**: Windows, Linux, Android. Activated via `--rhi vulkan`.

**Instance/device setup**: volk for dynamic function loading (`volkInitialize()` before any Vulkan call). Instance created with validation layer in debug builds (`VK_LAYER_KHRONOS_validation`). Physical device preference: discrete GPU. Logical device: graphics + transfer queues.

**Memory management**: VMA (Vulkan Memory Allocator) for suballocation. Three allocation strategies map to the same three heap types as DX12 (GPU-only, upload, readback).

**Descriptors**: Descriptor pool with pre-baked layouts — not full SM6.6 bindless. Shader binding via `#ifdef UZ_BINDLESS` guards allows the same HLSL to compile for Vulkan without bindless extensions.

**Synchronization**: Explicit pipeline barriers (`VkPipelineBarrier`) tracked per resource. `test_vulkan_barriers.cpp` has 78 tests covering all barrier transition combinations.

**Format conversion**: `vulkan_format_helpers.h` maps `RHIFormat` → `VkFormat` and `VkFormat` → `RHIFormat` for all 50+ formats in `rhi_types.h`.

**Implementation**: `runtime/engine/rhi/vulkan/` — 13 files (device, command list, swapchain, fence, GPU profiler, resources, format helpers).

### Metal Backend

**Target**: macOS, iOS. Activated via `--rhi metal`.

**Language**: Implementation files use `.mm` (Metal-cpp + Objective-C bridging via `__bridge`). Headers use forward-declared `MTL::` types so C++ callers never need `#include <Metal/Metal.h>`.

**Memory management**: No VMA — Metal manages GPU memory internally via storage modes (`MTLStorageModePrivate` for GPU-only, `MTLStorageModeShared` for upload/readback).

**Descriptors (bindless)**: Metal argument buffers tier 2 — equivalent to DX12 SM6.6 descriptor heaps. Texture and sampler argument buffers updated on resource creation, index passed as root constant.

**GPU family detection**: Startup queries `MTLGPUFamily` to map Metal GPU family → `RHIShaderModel` (Apple7+ = SM6.6 equivalent, Apple6 = SM6.0, older = SM5.0).

**Tracy integration**: `metal_tracy_gpu.h/.mm` — wraps `MTLCommandBuffer` timestamps for unified CPU/GPU profiling timeline.

**Implementation**: `runtime/engine/rhi/metal/` — 13 files (device, command list, swapchain.mm, fence, GPU profiler, resources, Tracy GPU wrapper).

### GPU Profiling

```cpp
UZ_GPU_TIMESTAMP(commandList, "ShadowPass");
UZ_GPU_TIMESTAMP(commandList, "GBufferPass");
UZ_GPU_FRAME_BEGIN(commandList);
UZ_GPU_FRAME_END(commandList);
```

- Triple-buffered query heap (avoid CPU stalls)
- Per-queue profiling: Graphics, Compute, Copy
- GPU timestamps converted to CPU time domain for unified timeline

### GPU Crash Debugging

```cpp
UZ_GPU_BREADCRUMB(commandList, "DrawMesh: {}", meshName);
```

- DRED (Device Removed Extended Data) enabled in dev builds
- GPU breadcrumbs via `WriteBufferImmediate()` — on TDR, breadcrumb trail shows last operations
- Breadcrumb buffer read back on device removal → logged with full context
- `UZ_VERIFY_HR(hr, "Failed to create resource")` logs HRESULT + DX12 debug layer message

### Debug Layer

- `ID3D12Debug` + GPU-based validation in debug builds
- All DX12 validation errors captured and routed to `UZ_LOG(LogRHI, Error, ...)`
- DXGI info queue filtered for our device (no noise from other processes)
- Debug layer disabled in release builds (significant perf overhead)

## Runtime Backend Selection

The RHI backend is configurable at startup via CLI, project config, or user config. This enables:
- **Developers** testing on different backends without recompiling
- **CI pipelines** running headless with specific backends
- **Shipped games** selecting the optimal backend per user's hardware

### Selection Priority (highest first)
1. CLI flag: `--rhi dx12`, `--rhi vulkan`, `--rhi metal`
2. Project config: `.uzproject` → `"rhi": "dx12"`
3. User config: `~/.uzengine/config.json` → `"default_rhi": "auto"`
4. Auto-detect: probe GPU capabilities, select best available

### Shader Model Override
- CLI: `--shader-model sm5`, `--shader-model sm6.6`
- Project config: `"shader_model": "sm6.6"`
- Auto-detect: probe SM6.6 support (Resource Binding Tier 3), fallback to SM5

### Post-Switch Shader Compilation
When the backend or shader model changes (different from cached shaders):
1. Check shader cache for target `(backend, shader_model)` pair
2. If missing, invoke the shader compiler before first frame
3. Display loading progress (or log in headless mode)
4. Cache new bytecode for future runs

This is modeled after UE5's Derived Data Cache — shaders are compiled lazily per backend and cached by content hash.

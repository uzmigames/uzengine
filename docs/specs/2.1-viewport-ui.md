# Spec 2.1 — Viewport & Core UI

> **Goal**: Native 3D viewport in VSCode, entity hierarchy panel, inspector panel, asset browser, console, and toolbar.

---

## How the Big Engines Solve This

### Unreal Engine 5.6

**Viewport**: Native Slate viewport widget. Multiple viewports (perspective, top, front, side). Each viewport has its own camera, render target, and input handler. Gizmos (translate/rotate/scale) rendered as overlays. Grid and axis indicators. Viewport overlays: wireframe, unlit, lit, buffer visualization. Real-time render at editor refresh rate.

**Hierarchy**: "World Outliner" — tree view of all actors. Drag-and-drop parenting. Search/filter by name, type, layer. Folder organization. Multi-select with Ctrl/Shift. Selection synced with viewport (click actor → selected in outliner, and vice-versa).

**Inspector**: "Details Panel" — property editor for selected actor. Auto-generated from `UPROPERTY()` reflection metadata. Categorized sections. Inline editors for vectors, colors, assets, enums. Undo/redo per property change. Multi-object editing.

**Asset browser**: "Content Browser" — two-panel file browser. Thumbnail previews for textures/meshes/materials. Drag-and-drop into viewport. Right-click import. Asset filtering by type. Dependencies view.

### Godot 4.x

**Viewport**: Native Vulkan/D3D12 surface embedded in the editor. 4 viewports (3D: perspective + ortho views). Gizmos for transform. Grid overlay. Camera orbit/pan/zoom. Shader-based overlay rendering for gizmos and selection.

**Hierarchy**: "Scene" dock — tree view of nodes. Drag-and-drop reparenting. Search. Node type icons. Right-click context menu (add child, rename, delete). Selection synced with viewport.

**Inspector**: "Inspector" dock — auto-generated from `@export` annotations and `_get_property_list()`. Sections per component/resource. Custom inspector plugins for specialized editors.

**Asset browser**: "FileSystem" dock — directory tree + file list. Thumbnails. Drag-and-drop. Import settings on selection.

### Unity 6

**Viewport**: "Scene View" — render texture displayed in editor panel. Camera controls (orbit, pan, fly). Gizmos rendered as overlay (Handles API). Scene view overlays (grid, camera frustums, light shapes). Game view separate (shows player camera).

**Hierarchy**: "Hierarchy" window — tree view of all GameObjects. Drag-and-drop parenting. Search. Prefab instance highlighting (bold names). Multi-scene support.

**Inspector**: "Inspector" window — auto-generated from serialized fields. Custom editors via `[CustomEditor]` attribute. Property drawers for custom types. Multi-edit support. Undo via `Undo.RecordObject()`.

**Asset browser**: "Project" window — two-column file browser. Thumbnails for assets. Drag-and-drop to scene/inspector. Search with type filters.

## The Problem

Building editor UI inside VSCode is fundamentally different from standalone editors:

1. **No native UI toolkit** — VSCode provides webview panels (HTML/CSS/JS), not native widgets
2. **Viewport rendering** — must embed a native DX12 surface inside VSCode somehow
3. **Panel communication** — each webview panel is isolated; coordinating selection/state requires message passing
4. **Performance** — webview rendering for UI is acceptable, but viewport MUST be native GPU
5. **Keyboard conflicts** — VSCode captures many shortcuts; viewport must receive raw input without interference

**Our advantage**: We've already proven H.264 streaming at 120 FPS. The native HWND approach gives us zero-overhead viewport. Webview panels for 2D UI are perfectly fine — all editor panels (inspector, hierarchy, etc.) are just HTML/CSS.

## UzEngine Approach

### Viewport Panel

**Native HWND** created by the runtime, positioned as a child/overlay of the VSCode window:

- Extension tracks the webview panel's screen position and size
- Runtime creates a borderless `WS_CHILD` or `WS_POPUP` window at that position
- DX12 swapchain presents directly to this HWND
- Mouse/keyboard events captured via `WM_INPUT` on the HWND (no webview interception)
- Gizmos, grid, selection highlight rendered by the runtime as 3D overlays
- Camera controls: orbit (Alt+LMB), pan (Alt+MMB), zoom (scroll), fly (RMB+WASD)

### Entity Hierarchy

Webview panel with reactive HTML tree:

- Tree view of all scene entities with expand/collapse
- Icons per component type (mesh, light, camera, etc.)
- Drag-and-drop reparenting (updates `HierarchyComponent`)
- Search/filter by name
- Click entity → sends selection to extension host → N-API → runtime highlights in viewport
- Click entity in viewport → runtime sends selection back → hierarchy scrolls to entity

### Inspector Panel

Webview panel showing properties of selected entity:

- Auto-generated from component data (transform fields, material parameters, light settings)
- Inline editors: vec3 (3 number inputs), color (picker), asset reference (path + browse button), enum (dropdown)
- Property changes → N-API → runtime applies immediately (live preview)
- Undo/redo stack per property

### Asset Browser

Webview panel for `content/` directory:

- Two-panel: directory tree + file grid
- Thumbnail previews (textures shown inline, meshes show wireframe preview)
- Drag-and-drop assets into hierarchy or inspector fields
- Right-click: import, rename, delete, show in explorer
- File type filtering

### Console Panel

Webview panel showing engine logs:

- Real-time streaming from `UZ_LOG()` via N-API callbacks
- Category filtering (LogRHI, LogRenderer, LogPhysics, etc.)
- Verbosity filtering (Error, Warning, Info, Debug)
- Search
- Clear / pause

### Toolbar

Webview panel (or status bar items):

- Play / Pause / Stop buttons → control runtime simulation
- Transform mode: Translate (W) / Rotate (E) / Scale (R)
- Snap toggle + settings
- Grid toggle
- Camera speed

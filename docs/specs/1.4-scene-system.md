# Spec 1.4 — Scene System

> **Goal**: ECS, transform hierarchy, component system, scene serialization, prefabs, asset references, hot-reload — load and render complete scenes.

---

## How the Big Engines Solve This

### Unreal Engine 5.6

**Entity model**: Hybrid OOP. `UWorld` contains `AActors`, each actor has `UActorComponents`. Traditional OOP hierarchy — `AActor` → `APawn` → `ACharacter`. **Mass Entity** (archetype ECS) added for large-scale simulation (crowds, 100K+ entities) but most gameplay uses the classic actor model.

**Transform hierarchy**: `USceneComponent` is the parent of all spatially-positioned components. `AttachToComponent()` creates parent-child relationships. Transform has `RelativeLocation/Rotation/Scale` (local) and computed `WorldTransform`. Dirty flag propagation via `MarkRenderTransformDirty()`.

**Mobility**: `EComponentMobility::Static` (baked lighting, no transform updates), `Stationary` (baked lighting, movable), `Movable` (fully dynamic). This drives optimization — static objects skip transform updates and use precomputed lighting.

**Serialization**: `FArchive` for binary serialization. `FObjectAndNameAsStringProxyArchive` for text. `.umap` (binary level) and `.uasset` (binary asset). Not human-readable — requires editor to modify. UE5 experimented with JSON (`FJsonArchiveOutputFormatter`) but it's not the default.

**Prefabs**: `UBlueprint` system — visual scripting class that defines actor hierarchy + default component values. Instantiated via `SpawnActor<T>()`. Blueprint instances can override parent defaults.

**Asset references**: `FSoftObjectPath` — string path with lazy loading. `TSoftObjectPtr<T>` for typed lazy refs. `FStreamableManager` for async loading. Content hash for cook pipeline validation.

### Godot 4.x

**Entity model**: Node tree (pure OOP). Every entity is a `Node` in a `SceneTree`. Nodes have parent-child relationships forming a tree. `Node3D` adds 3D transform. Inheritance: `Node` → `Node3D` → `MeshInstance3D`, `Camera3D`, `DirectionalLight3D`, etc.

**Transform hierarchy**: `Node3D.transform` (local), `Node3D.global_transform` (computed world). Automatic propagation — modifying parent recalculates all children. `top_level = true` breaks hierarchy (child uses world transform). No dirty flags — recomputed on access via `_update_transform()`.

**Serialization**: `.tscn` (text scene) — custom INI-like format, human-readable and diffable. `.scn` (binary, compressed). Text format is the default and recommended — great for version control. **This is a key Godot advantage** — scenes are easily inspected and merged.

**Prefabs**: "Scene inheritance" — a scene can inherit from another scene, overriding specific properties. `PackedScene` is the instantiation unit. `scene.instantiate()` creates a live instance. No Blueprint visual scripting equivalent.

**Asset references**: `ResourceLoader::load("res://path")` — path-based, loaded on demand. `@export` annotations for editor-exposed references. UID-based tracking (added 4.3) for rename-safe references.

### Unity 6

**Entity model**: Two systems. **Classic**: `GameObject` + `MonoBehaviour` (OOP, managed C#). **DOTS ECS**: `Entity` + `IComponentData` (value-type structs) + `ISystem`/`SystemBase`. Archetype storage — entities with same component set stored in contiguous 16KB chunks. `EntityManager` handles creation/destruction.

**Transform hierarchy**: Classic: `Transform` component with parent/child. DOTS: `LocalTransform` + `Parent` + `Child` components — hierarchy flattened into components, processed by `TransformSystemGroup`. `LocalToWorld` computed matrix cached per entity.

**Serialization**: Classic: YAML (`.unity` scenes, `.prefab`). DOTS: `EntityScene` binary blobs + `SubScene` streaming. The YAML format is theoretically human-readable but **in practice nearly impossible** to merge — Unity's YAML has deeply nested GUIDs that cause constant conflicts.

**Prefabs**: `.prefab` — YAML-based. Nested prefabs and prefab variants (override parent). Prefab instances track overrides per-property. `PrefabUtility` API for runtime instantiation.

**Asset references**: GUID-based (`m_FileID`, `m_PathID`). `AssetDatabase` for editor, `Resources.Load` / `Addressables` for runtime. Addressable system handles async loading with reference counting.

## The Problem

The scene system connects the renderer to gameplay. It must:

1. **Be ECS-native** — not a hybrid like Unreal/Unity where ECS is bolted on. ECS from day one for cache coherency and parallelism.
2. **Support hierarchy** — parent-child transforms are fundamental (character → weapon → particles)
3. **Serialize to JSON** — human-readable, LLM-friendly, diffable (like Godot's `.tscn` but better — JSON is universal)
4. **Lazy-load components** — no eager registration, scene drives what components exist (our "Component System — Lazy, Scene-Driven Architecture" from architecture.md)
5. **Hot-reload assets** — modify texture/material/scene on disk → updates in viewport instantly

Unity's YAML is a disaster for merging. Unreal's binary formats are opaque. Godot's `.tscn` is close but non-standard. JSON gives us the best of all worlds — universal tooling, LLM-compatible, schema-validatable.

## UzEngine Approach

### ECS (entt)

**Why entt**: Header-only, MIT, C++17. Fastest sparse-set ECS in benchmarks. O(1) component add/remove (no archetype migration like Unity DOTS). 100K entities create/destroy in <1ms.

```cpp
auto& registry = scene.GetRegistry();

// Create entity with components
auto entity = registry.create();
registry.emplace<TransformComponent>(entity, Vec3::Zero(), Quat::Identity(), Vec3::One());
registry.emplace<MeshComponent>(entity, meshHandle, materialHandle);
registry.emplace<LightComponent>(entity, LightType::Point, LinearColor::White(), 10.0f);

// System iteration (cache-friendly)
auto view = registry.view<TransformComponent, MeshComponent>();
view.each([](auto entity, TransformComponent& t, MeshComponent& m) {
    // Process — contiguous memory access
});
```

### Transform Hierarchy

**`TransformComponent`**: Local position, rotation, scale. World matrix cached, recomputed on dirty.

**`HierarchyComponent`**: Parent entity, first child, next sibling (linked list in ECS components). Dirty flag propagation — marking parent dirty cascades to all children.

**Mobility**: `TransformComponent::mobility` — `Static` (skip updates, bake lighting), `Movable` (per-frame updates).

```cpp
struct TransformComponent {
    Vec3 localPosition;
    Quat localRotation;
    Vec3 localScale = Vec3::One();
    Mat4 worldMatrix;           // Cached, recomputed when dirty
    Mobility mobility = Mobility::Movable;
    bool dirty = true;
};

struct HierarchyComponent {
    entt::entity parent = entt::null;
    entt::entity firstChild = entt::null;
    entt::entity nextSibling = entt::null;
};
```

**Transform system** runs early each frame: iterate dirty transforms, propagate to children, update world matrices. Static entities skipped entirely.

### Core Components

| Component | Data | Purpose |
|-----------|------|---------|
| `TransformComponent` | position, rotation, scale, worldMatrix, mobility | Spatial position |
| `HierarchyComponent` | parent, firstChild, nextSibling | Parent-child tree |
| `MeshComponent` | meshHandle, materialHandle | Renderable geometry |
| `LightComponent` | type, color, intensity, range, castShadows | Light source |
| `CameraComponent` | fov, near, far, isActive | View camera |
| `NameComponent` | string | Debug/editor display name |
| `TagComponent` | bitfield | Filtering, layer masks |

### Lazy Component Registration

Per architecture.md — **no components registered at boot**. Scene file declares which component types are used, only those are registered:

```
Engine Boot → Empty registry (zero components)
     │
Open Scene → Parse .uzscene → Discover component types
     │
Register → Only register types found in scene
     │
Instantiate → Create entities per scene data
     │
Close Scene → Destroy instances → Unregister unused types
```

### Scene Serialization (`.uzscene`)

JSON format, schema-validated:

```json
{
  "name": "TestScene",
  "version": "1.0",
  "entities": [
    {
      "name": "DirectionalLight",
      "components": {
        "transform": {
          "position": [0, 10, 0],
          "rotation": [45, -30, 0],
          "scale": [1, 1, 1],
          "mobility": "static"
        },
        "light": {
          "type": "directional",
          "color": [1.0, 0.95, 0.85],
          "intensity": 3.0,
          "cast_shadows": true,
          "shadow_cascades": 4
        }
      }
    },
    {
      "name": "PlayerSpawn",
      "components": {
        "transform": { "position": [0, 0, 0] }
      },
      "children": [
        {
          "name": "Camera",
          "components": {
            "transform": { "position": [0, 1.7, 0] },
            "camera": { "fov": 75, "near": 0.1, "far": 1000, "active": true }
          }
        }
      ]
    }
  ]
}
```

**Why JSON over Godot's `.tscn`**: JSON is universal — every language/tool can parse it. Schema validation via JSON Schema. LLMs generate valid JSON natively. Diffable in Git.

### Prefabs (`.uzprefab`)

Same format as `.uzscene` but represents a reusable entity template:

```json
{
  "name": "StreetLamp",
  "components": {
    "transform": {},
    "mesh": { "asset": "content/meshes/street_lamp.uzmesh" }
  },
  "children": [
    {
      "name": "LampLight",
      "components": {
        "transform": { "position": [0, 3.5, 0] },
        "light": { "type": "point", "color": [1, 0.9, 0.7], "intensity": 5, "range": 15 }
      }
    }
  ]
}
```

Instantiation: `scene.InstantiatePrefab("content/prefabs/street_lamp.uzprefab", transform);`

### Asset References

Path-based with content hash validation:

```json
{ "mesh": { "asset": "content/meshes/bunny.uzmesh" } }
```

- `AssetManager` resolves paths, caches loaded assets
- Broken references detected on load → logged as error
- Content hash stored in asset manifest — detects corrupted/modified files
- Async loading via task system (background priority)

### Hot Reload

| Asset Type | Detection | Action |
|-----------|-----------|--------|
| Textures | File watcher | Re-import → upload to GPU → swap descriptor |
| Materials | File watcher | Re-parse JSON → recompile shader (if graph changed) → swap PSO |
| Scenes | Manual reload | Re-parse → diff → apply changes (preserve camera/selection) |
| Shaders | File watcher | Recompile → swap PSO |
| Configs | File watcher | Re-parse → apply |

File watcher uses `ReadDirectoryChangesW` (Windows) on `content/` and `shaders/` directories.

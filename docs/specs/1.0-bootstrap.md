# Spec 1.0 — Bootstrap & Project Setup

> **Goal**: Compilable project with build system, logging, assertions, profiling, memory foundation, platform window, input, and config system.

---

## How the Big Engines Solve This

### Unreal Engine 5.6

**Build system**: Custom build tool (UnrealBuildTool, C#) + UnrealHeaderTool for code generation. `.Build.cs` and `.Target.cs` files define module dependencies. Extremely powerful but **massive** — UBT itself is ~100K lines of C#. Build times for a fresh engine are 30-60 minutes.

**Logging**: `UE_LOG(LogCategory, Verbosity, TEXT("..."))` macro system. Categories declared with `DECLARE_LOG_CATEGORY_EXTERN` / `DEFINE_LOG_CATEGORY`. 6 verbosity levels (Fatal → VeryVerbose). Output to console, file (with rotation), Visual Studio output window. Compile-time stripping of verbose levels in shipping builds.

**Assertions**: `check(cond)` (fatal, stripped in shipping), `ensure(cond)` (non-fatal, logs callstack + continues), `verify(cond)` (not stripped — side effects evaluated). `checkf()`/`ensureMsgf()` for formatted messages. First `ensure` triggers a crash report callstack snapshot.

**Profiling**: `SCOPE_CYCLE_COUNTER(StatId)` RAII counters. `DECLARE_STATS_GROUP` / `DECLARE_CYCLE_STAT` for stat declarations. Stats grouped hierarchically (Rendering, Physics, etc.) and displayed in-editor or via `stat` console commands. Unreal Insights for deep timeline profiling.

**Memory**: Custom allocators (`FMallocBinned3` default, `FMallocBinned2` fallback). `FMemory::Malloc/Free/Realloc` replace global `new/delete`. Per-subsystem memory tracking via `LLM` (Low Level Memory tracker). No garbage collector for C++ — GC only for UObject (reflection-based mark-and-sweep).

**Window/Input**: `FGenericWindow` / `FWindowsWindow` abstraction. `FSlateApplication` processes input events from OS. `FInputDeviceScope`, `IInputDevice` interface. Action/axis mappings in project settings. Enhanced Input System (`UInputMappingContext`, `UInputAction`) for modern input handling.

**Config**: `.ini` files cascading (Engine → Project → User → CLI). `GConfig->GetFloat()` API. `UPROPERTY(Config)` auto-binds properties to ini sections.

### Godot 4.x

**Build system**: SCons (Python-based). `SConstruct` + per-module `SCsub` files. ~15-20 minute fresh build. Cross-compilation via SCons platform configs.

**Logging**: `print()` for basic output, `ERR_PRINT()` / `WARN_PRINT()` macros. `Logger` class writes to stdout + file. No category system (simpler than Unreal). Controlled via `--verbose` and `--quiet` CLI flags.

**Assertions**: `ERR_FAIL_COND(cond)` (returns from function), `ERR_FAIL_NULL(ptr)`, `ERR_FAIL_INDEX(idx, size)`, `CRASH_COND(cond)` (fatal). Error handler hooks allow custom error processing. `DEV_ASSERT` stripped in release.

**Profiling**: `OS::get_singleton()->benchmark_begin/end()`. Custom profiler server — editor connects via network. Frame profiler, visual profiler, network profiler built into editor.

**Memory**: Custom `Memory::alloc_static()` / `Memory::free_static()`. `memnew(Type)` / `memdelete(ptr)` macros. `ObjectDB` tracks all `Object` instances. Leak detection on shutdown. No per-subsystem budgets.

**Window/Input**: `DisplayServer` singleton per platform. `Input` singleton for polling. `InputMap` for action mapping (data-driven, project settings). `InputEvent` hierarchy (key, mouse, gamepad, touch).

**Config**: `ProjectSettings` singleton, `.godot` project file. `ConfigFile` for INI-style configs. Settings cascade: project → editor → user.

### Unity 6

**Build system**: MSBuild for C# assemblies. il2cpp for AOT compilation. Gradle for Android. Assembly definitions (`.asmdef`) for module boundaries.

**Logging**: `Debug.Log/LogWarning/LogError`. `ILogger` interface. Stack traces attached automatically. Console window with filtering by type. `[Conditional("DEBUG")]` for stripping.

**Assertions**: `Debug.Assert()` (dev only). Standard C# `try/catch/finally`. `NullReferenceException` common (managed runtime). No macro-based assertions.

**Profiling**: Built-in Profiler (CPU, GPU, Memory, Audio, Physics). `Profiler.BeginSample/EndSample` manual instrumentation. Deep profiling mode captures all calls. Memory Profiler package for detailed snapshots.

**Memory**: C# GC (Boehm or incremental) for managed code. `NativeArray<T>` / `NativeList<T>` for unmanaged (Burst-compatible). `UnsafeUtility` for raw allocation. Memory budgets for asset streaming.

**Window/Input**: `Screen` / `Display` abstraction. New Input System (`InputAction`, `InputActionMap`, `PlayerInput`). Action-based with composite bindings. Control schemes for device switching.

**Config**: `PlayerSettings` in editor. Runtime `Application` class. `PlayerPrefs` for user settings. `ScriptableObject` for config data.

## The Problem

Every engine needs a solid foundation layer before any rendering or gameplay can happen. The bootstrap layer must:

1. **Build reliably** — fresh clone to running binary in minutes, not hours
2. **Log everything** — every subsystem must be observable from day one
3. **Fail explicitly** — crashes must produce actionable diagnostics, not silent corruption
4. **Profile by default** — performance must be measurable from the first frame
5. **Own memory** — deterministic allocation, no GC pauses, per-subsystem tracking
6. **Abstract the platform** — window creation, input capture, file I/O behind clean interfaces
7. **Configure flexibly** — no hardcoded values, cascading overrides from engine defaults to CLI flags

The big engines get this right but at massive complexity cost. Unreal's build system alone is a project unto itself. Unity's GC creates frame-time spikes. Godot's simpler approach sacrifices per-subsystem granularity.

## UzEngine Approach

### Build System
**Zig build (primary) + CMake fallback.** Zig gives us fast incremental builds (<5s target), cross-compilation, and C/C++ compilation via `zig cc`. CMake fallback for MSVC debugging with PIX and GPU-based validation. Setup script (`scripts/setup.ps1`) handles vcpkg bootstrap and dependency fetch.

**Why not SCons/UBT**: We don't need code generation (no UObject reflection), and SCons is slow. Zig is the fastest C/C++ build system available.

### Logging
**Category-based, compile-time filtered, Unreal-style macros.**

```cpp
UZ_DECLARE_LOG_CATEGORY(LogRHI);
UZ_LOG(LogRHI, Info, "Device created: {}", adapterName);
```

- 6 levels: Fatal → Error → Warning → Info → Debug → Trace
- Compile-time strip of Debug/Trace in shipping (like Unreal, unlike Godot which has no categories)
- `fmt` library for formatting (not printf — type-safe, fast)
- Pluggable backends: console, file (with rotation), debugger output
- Thread-safe with minimal locking

### Assertions
**Unreal-style with crash context.**

```cpp
UZ_CHECK(ptr != nullptr);           // Fatal in debug, stripped in shipping
UZ_ENSURE(result.IsValid());        // Non-fatal, logs + continues
UZ_VERIFY(Init());                  // Never stripped (side effects)
UZ_CHECKF(idx < size, "OOB: {}/{}", idx, size);  // Fatal with message
```

### CPU Profiling
**RAII scope-based, hierarchical stat groups.**

```cpp
UZ_PROFILE_SCOPE(Rendering, DrawOpaquePass);
UZ_STAT_INCREMENT(Rendering, DrawCalls);
UZ_PROFILE_FRAME_MARK();
```

- Stat groups: Rendering, RHI, Physics, Scene, Memory, IO
- Zero-cost when disabled via `UZ_PROFILING_ENABLED`
- CSV export for offline analysis (Phase 1), live streaming to editor (Phase 2)

### Memory
**Rust-inspired ownership model, no GC.**

```cpp
Own<T>     — unique_ptr semantics, single owner, move-only
Ref<T>     — non-owning immutable borrow, debug-validated lifetime
RefMut<T>  — exclusive mutable borrow, debug-asserts no other borrows
```

- Debug builds: borrow checker tracks active borrows, asserts on violations
- Release builds: zero-cost raw pointers
- Custom allocators: linear, pool, frame (cleared each frame)
- Per-subsystem memory tracking via named arenas
- `mimalloc` as global allocator replacement (2x faster than default)

### Platform Window
**`PlatformWindow` abstraction, Win32 first.**

- Win32 `CreateWindowEx` + `WndProc` message loop
- Resizable, closeable, fullscreen toggle
- HWND exposed for DX12 swapchain binding
- Platform-specific code isolated in `platform/windows/`

### Input System
**Runtime-owned, data-driven action maps.**

```cpp
UZ_INPUT_ACTION("Editor.TranslateGizmo", Key::W);
if (Input::IsActionJustPressed("Game.Jump")) { ... }
HitResult hit = Input::PickAtScreenPos(mouseX, mouseY, camera, scene);
```

- Raw input via Win32 `WM_INPUT` (not `WM_KEYDOWN` — lower latency)
- Action maps with layers and priority (Editor > Game > System)
- Mouse picking via raycasting (not DOM, unlike VSCode webview)
- Gamepad via XInput/DirectInput
- Input recording/playback for automated testing

### Config System
**JSON `.uzproject`, cascading resolution.**

```
CLI flags → Scene overrides → .uzproject → Engine defaults
```

- Every parameter has a compiled-in default
- JSON Schema validation on load
- Unknown keys warn, invalid values error with clear message
- Hot-reloadable where possible (Phase 2)

## Deliverables

| Task | Acceptance Criteria |
|------|-------------------|
| Build system setup | `zig build` and `cmake --build` both produce executable |
| Setup script | Fresh clone → run script → builds successfully |
| Directory structure | All runtime directories exist per architecture.md |
| Logging system | Logs appear in console with category/level/timestamp |
| Assertion macros | Fatal asserts crash with stack trace, ensure logs + continues |
| CPU profiler | Profile data queryable, outputs to console/file |
| Memory foundation | Double-borrow asserts in debug, zero-cost in release |
| Platform window | Window opens, receives input, resizable, closeable |
| Input system | Key press/release/held detectable, gamepad works |
| Config system | CLI args override project settings override engine defaults |
| JSON schemas | `uzproject.schema.json` validates correctly |
| Test harness | `zig build test` runs and passes |

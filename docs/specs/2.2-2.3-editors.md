# Spec 2.2/2.3 — Core & Advanced Editors

> **Goal**: Specialized editor panels for materials, animation, AI, VFX, terrain, scripting, localization, and full level editing.

---

## How the Big Engines Solve This

### Unreal Engine 5.6

**Material editor**: Node-based shader graph. Hundreds of node types. Live 3D preview (sphere/plane/custom mesh). Compile-on-save → instant viewport update. Output: Material Expression tree → HLSL code generation → PSO. Stored as binary `.uasset`.

**Animation editors**: AnimGraph (node-based state machine), Sequencer (timeline/keyframe editor), Control Rig (IK/procedural animation editor), Blend Space editor (1D/2D), Montage editor. All native Slate UI.

**Behavior tree**: Node-based editor. Task, decorator, service nodes. Blackboard key editor. Runtime debugging (highlights active node during play).

**VFX (Niagara)**: Full node graph editor. Emitter stack visualization. Module parameters with real-time preview. GPU particle debugging. Curve editors for size/color over life.

**Level editor**: Full 3D scene editing. Multi-select, copy/paste, undo/redo (transaction system). Snap to grid/surface. Vertex snapping. Brush-based BSP geometry. Landscape sculpting + painting.

### Godot 4.x

**Shader editor**: Text-based (GLSL-like shader language) or VisualShader (node graph). Live preview. Simpler than Unreal — fewer nodes but more accessible.

**Animation**: AnimationPlayer timeline. AnimationTree state machine editor. Blend space editor. Simpler than Unreal but covers most use cases.

**No built-in**: behavior tree editor, VFX graph editor, visual script editor (GDScript is the scripting solution). Community addons fill gaps.

**Level editor**: 3D viewport with gizmos. GridMap for tile-based levels. CSG for prototype geometry. Multi-select, undo/redo.

### Unity 6

**Shader Graph**: Node-based (URP/HDRP). Master stack pattern. Preview per node. Generates HLSL. Stored as `.shadergraph` (JSON-like).

**Animation**: Animator Controller (state machine), Animation window (keyframe editor), Timeline (cinematic sequencer). Avatar system for retargeting.

**VFX Graph**: Node-based GPU particle editor (HDRP only). Contexts: Spawn, Initialize, Update, Output. Subgraph support. Live preview.

**Visual scripting**: Bolt (discontinued) / custom solutions. Unity removed built-in visual scripting.

**Scene editor**: Hierarchy + Scene View. ProBuilder for in-editor mesh editing. Terrain tools. Cinemachine for camera. Multi-edit.

## The Problem

Each editor domain has unique UI requirements, but they share common patterns:

1. **Node graph renderer** — materials, visual scripts, behavior trees, VFX, anim controllers all use node graphs
2. **Timeline/keyframe editor** — animation sequences, cinematics
3. **2D/3D preview** — materials need a preview sphere, VFX need particle preview, animations need skeletal preview
4. **Property panels** — every editor needs parameter editing
5. **Undo/redo** — every editor needs transaction support

**Our advantage**: All editors are webview panels using the same HTML/CSS component library. A shared node-graph renderer component can be reused across 5+ editors. All data is JSON — LLMs can generate/modify without any editor at all.

## UzEngine Approach

### Shared Components

All editors built on a common webview component library:

| Component | Used By |
|-----------|---------|
| **Node Graph Renderer** | Shader Graph, Visual Script, Behavior Tree, VFX Graph, Anim Controller |
| **Timeline Editor** | Animation Sequence, Cinematic Sequencer |
| **Property Panel** | All editors (parameter editing) |
| **Curve Editor** | Animation (keyframe curves), VFX (size/color over life) |
| **Color Picker** | Material, VFX, Lighting |
| **Asset Selector** | All editors (texture/mesh/sound references) |

### 2.2 — Core Editors

| Editor | Data Format | Key Features |
|--------|-------------|-------------|
| **Shader Graph** | `.uzmaterial` (JSON graph) | Node-based material creation. PBR outputs. Custom HLSL blocks. Live 3D preview. Compile → shader permutations. |
| **Animation Controller** | `.uzanimcontroller` (JSON) | State machine nodes. Transitions with blend time. Blend trees (1D/2D). Layer support. Live skeleton preview. |
| **Behavior Tree** | `.uzbehavior` (JSON) | Task, decorator, service nodes. Blackboard editor. Runtime debugging (active node highlight). |
| **Localization** | `.uzlocale` (JSON) | String table manager. Culture overview. Missing translation tracker. Import/export. |
| **UI Editor** | `.uzui` (HTML/CSS/JSON) | WYSIWYG HTML/CSS game UI. Data binding setup. Event wiring. Live preview in viewport. |

### 2.3 — Advanced Editors

| Editor | Data Format | Key Features |
|--------|-------------|-------------|
| **Visual Script** | `.uzscript` (JSON graph) | Blueprint-style node graph. Generates C++/Lua code. Variables, events, functions. |
| **Control Rig** | `.uzcontrolrig` (JSON) | IK solvers (FABRIK, CCD). Bone constraints. Procedural animation. Runtime evaluation. |
| **Animation Sequence** | `.uzanimsequence` (JSON + binary) | Timeline, keyframes, curves, events. Additive layers. Preview with skeleton. |
| **VFX Graph** | `.uzvfx` (JSON graph) | Emitter stack. Module parameters. GPU particle preview. Curve editors. |
| **Terrain** | heightmap + splatmap | Sculpt tools, paint layers. Foliage placement. LOD preview. |
| **Scene Editor (full)** | `.uzscene` (JSON) | Multi-select, copy/paste, undo/redo, snap, grid. Full level editing workflow. |

### All Formats are JSON → LLM-Generatable

Every editor's data format is JSON with a JSON Schema. An LLM can:
- Generate a complete material from a text description
- Create a behavior tree for "patrol → chase → attack"
- Write a VFX system for "fire explosion"
- Build a UI layout for "health bar + minimap"

The editors are for human convenience. The JSON format is the source of truth.

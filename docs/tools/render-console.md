## 1. Overview & Goals

Every rendering decision in UzEngine is governed by a **Console Variable (CVar)** in the `r.*` namespace. The Render Console system makes the entire render pipeline live-tweakable at runtime: shadow resolution, anti-aliasing method, LOD bias, post-process intensity, debug visualization mode, and hundreds more parameters can be changed on the fly without restarting the engine or recompiling shaders.

### Design Principles

1. **Every knob is a CVar** -- No hardcoded rendering constants. If it affects a pixel, it has a CVar.
2. **Immediate effect** -- CVar changes take effect on the next frame (or at the next safe boundary for expensive rebuilds like PSO recompilation).
3. **Layered persistence** -- CVars have a default value baked into C++, an optional project-level override (`project/render.cfg`), and an optional user-level override (`%APPDATA%/UzEngine/user_render.cfg`). The final value is `user > project > default`.
4. **Scalability presets** -- Bundled CVar configurations (Low/Medium/High/Ultra) that map directly to game Settings menus. One call applies dozens of CVars at once.
5. **AI-friendly config files** -- All `.cfg` files are INI-like plain text, easily read and generated by LLMs.
6. **IPC-first** -- Every CVar is readable and writable from the VSCode editor via IPC, enabling the Render Console Panel and AI-assisted tuning.

### Target Users

| User | Use Case |
|------|----------|
| **Graphics Engineer** | Deep per-parameter tuning: shadow cascade distances, GI probe update rates, TAA blend factors, buffer visualization modes |
| **Game Designer / Level Artist** | Quick quality toggles during playtesting: disable SSAO to check base lighting, force LOD0 to inspect models, switch to wireframe mode |
| **End User (Game Settings Screen)** | Select a scalability preset (Low/Medium/High/Ultra) from the in-game Settings menu, with per-category overrides |
| **AI Agent (Claude via MCP)** | Programmatic rendering optimization: read GPU timing data, adjust CVars, measure impact, iterate |

### Console Variable Lifecycle

```
Engine Startup
     |
     v
[1] Load hardcoded defaults (RENDER_CVAR_* macros in C++)
     |
     v
[2] Load project/render.cfg (overrides defaults for this project)
     |
     v
[3] Load %APPDATA%/UzEngine/user_render.cfg (per-user overrides)
     |
     v
[4] Apply command-line overrides (--cvar r.VSync=0)
     |
     v
[5] Runtime: CVars read each frame by renderer subsystems
     |  ^--- IPC / Console / Lua can write CVars at any time
     |
     v
Engine Shutdown
     |
     v
[6] Optionally save modified CVars to user_render.cfg
```

## 2. Console Variable (CVar) System

### 2.1 CVar Types

Every render CVar has a strongly-typed value, a valid range, and metadata for the editor UI.

| Type | C++ Type | Editor Widget | Example |
|------|----------|---------------|---------|
| `Int` | `int32_t` | Slider or spinner | `r.Shadow.Quality = 2` |
| `Float` | `float` | Slider (continuous) | `r.Bloom.Intensity = 0.8` |
| `Bool` | `bool` (stored as int 0/1) | Toggle checkbox | `r.VSync = 1` |
| `Enum` | `int32_t` (named values) | Dropdown | `r.AA.Method = 2` (TAA) |

### 2.2 Registration Macros

CVars are declared in the C++ source files of the subsystem that owns them. Registration happens at static initialization time.

```cpp
// src/renderer/cvar_system.h

// ---- Registration macros ----

// Integer CVar with min/max range
#define RENDER_CVAR_INT(name, default_val, min_val, max_val, desc) \
    static CVar<int> name(#name, default_val, min_val, max_val, desc, CVarFlags::Render)

// Float CVar with min/max range
#define RENDER_CVAR_FLOAT(name, default_val, min_val, max_val, desc) \
    static CVar<float> name(#name, default_val, min_val, max_val, desc, CVarFlags::Render)

// Boolean CVar (stored as int 0/1)
#define RENDER_CVAR_BOOL(name, default_val, desc) \
    static CVar<int> name(#name, default_val ? 1 : 0, 0, 1, desc, CVarFlags::Render)

// Enum CVar with named value list
#define RENDER_CVAR_ENUM(name, default_val, enum_names, desc) \
    static CVar<int> name(#name, default_val, 0, (int)enum_names.size()-1, desc, \
                          CVarFlags::Render | CVarFlags::Enum, enum_names)
```

**Usage example** (in the shadow system source file):

```cpp
// src/renderer/shadow_system.cpp

#include "cvar_system.h"

// Shadow CVars -- registered at static init, available before first frame
RENDER_CVAR_BOOL(r_Shadow_Enable, true, "Master shadow toggle");
RENDER_CVAR_INT(r_Shadow_Quality, 2, 0, 4, "Shadow map resolution tier: 0=512, 1=1024, 2=2048, 3=4096, 4=8192");
RENDER_CVAR_FLOAT(r_Shadow_DistanceScale, 1.0f, 0.1f, 5.0f, "Shadow draw distance multiplier");
RENDER_CVAR_INT(r_Shadow_CascadeCount, 3, 1, 4, "Number of CSM cascades");

static const std::vector<std::string> s_shadow_filter_names = {"Hard", "PCF", "PCSS"};
RENDER_CVAR_ENUM(r_Shadow_Filter, 1, s_shadow_filter_names, "Shadow filtering: 0=Hard, 1=PCF, 2=PCSS");
```

### 2.3 Runtime Access

```cpp
// Read (fast path -- called per-frame by renderer, no lock needed)
int shadow_quality = CVarSystem::Get("r.Shadow.Quality")->AsInt();
float bloom_intensity = CVarSystem::Get("r.Bloom.Intensity")->AsFloat();
bool vsync = CVarSystem::Get("r.VSync")->AsBool();

// Write (queued to apply at next frame boundary)
CVarSystem::Set("r.Shadow.Quality", 3);
CVarSystem::Set("r.Bloom.Intensity", 1.2f);
CVarSystem::Set("r.VSync", false);

// Cached pointer for hot-path reads (avoid hash lookup every frame)
static CVar<int>* s_shadow_quality = CVarSystem::Get("r.Shadow.Quality");
int q = s_shadow_quality->AsInt();  // direct read, no map lookup
```

### 2.4 Change Callbacks

Some CVar changes require expensive work (PSO recompilation, texture streaming purge, render target reallocation). These CVars register an on-change callback that runs at the frame boundary.

```cpp
CVarSystem::Get("r.Shadow.Quality")->OnChange([](const CVar<int>& var) {
    // Shadow atlas resolution changed -- reallocate shadow atlas
    ShadowSystem::Get().ReallocateAtlas(ShadowQualityToResolution(var.AsInt()));
});

CVarSystem::Get("r.AA.Method")->OnChange([](const CVar<int>& var) {
    // AA method changed -- may need PSO recompile (shader variant change)
    PostProcessStack::Get().RebuildAAPipeline(static_cast<AAMethod>(var.AsInt()));
});

CVarSystem::Get("r.ScreenPercentage")->OnChange([](const CVar<int>& var) {
    // Render resolution changed -- reallocate all screen-size targets
    RenderTargetPool::Get().Resize(var.AsInt());
});
```

Callbacks are deferred to the **frame boundary** (between frames, after GPU idle) to avoid mid-frame resource invalidation. The `CVarSystem` maintains a dirty queue that is flushed once per frame.

### 2.5 CVar Flags

```cpp
enum class CVarFlags : uint32_t {
    None        = 0,
    Render      = 1 << 0,   // r.* namespace -- render CVar
    ReadOnly    = 1 << 1,   // cannot be changed at runtime (informational only)
    Enum        = 1 << 2,   // has named enum values
    Expensive   = 1 << 3,   // change triggers expensive rebuild (show progress indicator)
    UserFacing  = 1 << 4,   // appears in game Settings menus
    Cheat       = 1 << 5,   // disabled in shipping builds
    SaveToUser  = 1 << 6,   // persisted to user_render.cfg
    SaveToProj  = 1 << 7,   // persisted to project/render.cfg
};
```

### 2.6 Name Convention

CVar names use **dot-separated hierarchical naming** in the IPC/config layer, and **underscore-separated** C++ identifiers internally:

| Config / IPC name | C++ variable name | Category |
|---|---|---|
| `r.Shadow.Quality` | `r_Shadow_Quality` | Shadows |
| `r.AA.Method` | `r_AA_Method` | Anti-Aliasing |
| `r.Bloom.Intensity` | `r_Bloom_Intensity` | Post-Processing |
| `r.Debug.Mode` | `r_Debug_Mode` | Debug |

The `CVarSystem` automatically converts between the two forms. Config files and IPC always use the dot form.

## 3. Scalability Groups

Scalability groups bundle related CVars into named quality tiers. Each group has 4 levels (Low/Medium/High/Ultra) that map to specific CVar values. A master quality setting applies all groups simultaneously for a one-click Settings experience.

### 3.1 Group Definitions

| Group CVar | Controls | Description |
|------------|----------|-------------|
| `sg.ShadowQuality` | Shadow resolution, filter, cascades, distance | Shadow map fidelity |
| `sg.TextureQuality` | Texture max size, mip bias, streaming budget, anisotropy | Texture fidelity and VRAM |
| `sg.FoliageQuality` | Foliage density, draw distance, wind, max instances | Vegetation rendering cost |
| `sg.PostProcessQuality` | SSAO, bloom, DOF, motion blur, film grain | Post-process effect complexity |
| `sg.LightingQuality` | Max lights, GI method, reflections, exposure | Lighting complexity |
| `sg.AntiAliasingQuality` | AA method, TAA samples, upscale method | Anti-aliasing and upscaling |
| `sg.GeometryQuality` | LOD bias, culling distance, HZB, tessellation | Mesh detail and draw distance |

### 3.2 Master Preset

## 5. GPU Profiler Integration

The Render Console includes GPU profiling tools that leverage DX12 timestamp queries and Tracy GPU zones to provide frame-level performance data.

### 5.1 DX12 Timestamp Query System

Each render pass is bracketed by timestamp queries:

```cpp
// src/renderer/gpu_profiler.h

struct GPUTimerQuery {
    uint32_t begin_index;   // index into timestamp query heap
    uint32_t end_index;
    const char* pass_name;
    float last_ms;          // resolved time from previous frame
};

class GPUProfiler {
public:
    void BeginPass(ID3D12GraphicsCommandList* cmd, const char* name);
    void EndPass(ID3D12GraphicsCommandList* cmd);
    void ResolveQueries(ID3D12GraphicsCommandList* cmd);  // once per frame
    void ReadbackResults();  // after GPU completes, read resolved timestamps

    const std::vector<GPUTimerQuery>& GetPassTimings() const;
    float GetTotalGPUTimeMS() const;

private:
    ComPtr<ID3D12QueryHeap> m_timestamp_heap;   // D3D12_QUERY_HEAP_TYPE_TIMESTAMP
    ComPtr<ID3D12Resource>  m_readback_buffer;  // readback for resolved timestamps
    uint64_t m_gpu_frequency;                    // ticks per second
    std::vector<GPUTimerQuery> m_queries;
    static constexpr uint32_t MAX_QUERIES = 64;  // 32 passes x 2 (begin+end)
};
```

**Usage in the renderer**:

```cpp
void Renderer::RenderFrame(FrameContext& ctx) {
    auto* cmd = ctx.command_list;

    gpu.EndPass(cmd);

    gpu.EndPass(cmd);

    gpu.BeginPass(cmd, "SSR");
    RunSSR(cmd);
    gpu.EndPass(cmd);

    gpu.BeginPass(cmd, "Transparency");
    RenderTransparency(cmd);
    gpu.EndPass(cmd);

    gpu.BeginPass(cmd, "Skybox");
    RenderSkybox(cmd);
    gpu.EndPass(cmd);
```

#### Tiled Rendering for Large Screenshots

Screenshots larger than the GPU's max render target size (or that would exceed VRAM) use tiled rendering:

```
Target: 8192 x 8192 screenshot
GPU max RT: 4096 x 4096
Tile grid: 2x2 (4 tiles of 4096x4096 each)

  +----------+----------+
  | Tile 0,0 | Tile 1,0 |
  | (4096x   | (4096x   |
  |  4096)   |  4096)   |
  +----------+----------+
  | Tile 0,1 | Tile 1,1 |
  | (4096x   | (4096x   |
  |  4096)   |  4096)   |
  +----------+----------+

Each tile renders with an offset projection matrix:
  proj_tile = offset(col, row, grid_w, grid_h) * proj_full

Tiles are stitched on CPU after readback.
```

```cpp
// src/renderer/screenshot_system.h

class ScreenshotSystem {
public:
    // Capture a screenshot (may span multiple frames for tiled rendering)
    void CaptureAsync(const ScreenshotParams& params,
                      std::function<void(ScreenshotResult)> callback);

    // Tick -- called each frame to process pending tile renders
    void Update();

private:
    struct TileJob {
        int col, row;
        int grid_cols, grid_rows;
        int tile_width, tile_height;
        float4x4 tile_projection;
    };

    std::queue<TileJob> m_pending_tiles;
    std::vector<uint8_t> m_stitched_buffer;  // final assembled image
    ScreenshotParams m_current_params;
};
```

### 9.2 Thread Safety

- **Read path** (hot): CVars are read by the render thread every frame. Reads use `std::atomic<T>` for primitive types, so no mutex is needed. The render thread reads a consistent snapshot at frame start.
- **Write path** (cold): Writes come from the main thread (console, IPC, Lua). Writes go through `CVarRegistry::Set()` which atomically updates the value and adds the CVar to a dirty queue.
- **Dirty queue flush**: At the frame boundary (after GPU idle, before next frame submission), the main thread flushes the dirty queue and invokes on-change callbacks. This guarantees callbacks never fire mid-frame.
- **String CVars**: Not supported for render CVars. All render CVars are numeric (int, float, bool, enum) for atomic read performance.

```cpp
template<typename T>
class CVar : public CVarBase {
    std::atomic<T> m_value;  // lock-free read from render thread

public:
    T AsInt() const { return m_value.load(std::memory_order_relaxed); }

    void SetValue(T v) {
        T clamped = std::clamp(v, m_min, m_max);
        T old = m_value.exchange(clamped, std::memory_order_release);
        if (old != clamped && m_on_change) {
            CVarRegistry::Get().QueueDirty(this);
        }
    }
};
```

### 9.6 Command-Line CVar Overrides

CVars can be set from the command line when launching the engine:

```bash
render.exe --cvar r.VSync=0 --cvar r.Shadow.Quality=4 --cvar r.Debug.ShowStats=1
```

This is useful for automated testing, benchmarks, and CI pipelines. Command-line overrides have the highest priority and cannot be overwritten by config files.

## 3. Re-enable `AddParticleMeshRenderPass`
- [x] 3.1 Diagnosed via code + git archaeology (rhi-engineer): root cause = `particle_mesh_render_pass.cpp` execution callback called `SetPipeline` + `DrawIndexedIndirect` without ever calling `BeginRenderPass` / `SetViewport` / `SetScissor` / `EndRenderPass`. DX12 backend's `BeginRenderPass` is the sole `OMSetRenderTargets` site so the indirect draw landed with stale RTV/DSV from a prior pass (typically GBuffer slots — wrong format for HDR composite). Disable commit: `d0626fed5a2c56b9715f9e525008fcb657e8df5e` ("RC3+RC4: Disabled AddParticleRenderPass, AddTrailRenderPass, AddParticleMeshRenderPass — these need BeginRenderPass and DrawIndirect fixes").

## 1. Implementation
- [x] 1.1 Audit current DDGI pipeline — `engine/renderer/gi/ddgi_system.{h,cpp}` owns the probe atlases (irradiance + depth) and the probe-update CS dispatch. Existing `engine/vfx/lighting/vfx_ddgi_injection.{h,cpp}` (Karis attenuation + per-probe accumulation helpers) and `vfx_ddgi_emissive_feed.{h,cpp}` (GPU upload wrapper for `VfxEmissiveSample[kMaxSamples=32]`) were ALREADY shipped — they were sitting orphan, never instantiated by `SceneRenderer`.
- [x] 1.2 `VfxEmissiveSample` (the existing struct) is the equivalent of the proposed `VfxVirtualEmissiveLight` — position + linear-RGB radiance + influence radius. No new struct needed; the byte layout already matches the GPU buffer's `kMaxSamples` capacity.
- [x] 1.3 New `VfxDDGIBuildSampleForEmitter` helper in `engine/vfx/lighting/vfx_ddgi_injection.{h,cpp}` — pure CPU function that aggregates a single emitter's state into one virtual emissive sample (intensity scales by alive-fraction, influence radius floors at 1 m). Used by the gather path to produce the buffer contents.
- [x] 1.4 New `SceneRenderer::GatherAndUploadVfxEmissiveSamples` (`engine/renderer/frame/frame_vfx_inline.cpp`) walks active emitters, filters by `emissiveIntensity > 0` + `aliveCount > 0`, builds samples via the helper, and forwards them to `m_vfxDDGIEmissiveFeed.UploadFrame`. Called once per frame from `scene_render_frame.cpp` immediately after `DispatchVFXSort`.

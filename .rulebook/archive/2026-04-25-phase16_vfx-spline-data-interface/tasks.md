## 1. Implementation
- [x] 1.1 Audit `runtime/engine/` for an existing spline primitive — found `VfxSpline` in `engine/vfx/data_interfaces/vfx_spline_di.{h,cpp}` already shipped (centripetal Catmull-Rom + arc-length LUT + parametric / arc-length-uniform sampling). Sanity-tested with new endpoint + monotonicity unit tests.
- [x] 1.2 New `VfxSplineBuffer` (`engine/vfx/data_interfaces/vfx_spline_buffer.{h,cpp}`) wraps an upload-heap structured buffer of `VfxSplinePoint` (32 bytes — `static_assert(sizeof == 32)`); `Create` / `Destroy` / `RebuildAndUpload(spline, device)` lifecycle. Capacity clamps to `[2, kVfxSplineMaxResolution]`.
- [x] 1.3 `runtime/shaders/runtime/vfx/spline_di.hlsli` — bindless HLSL helpers: `SplineSampleAtU(idx, count, u)`, `SplineSampleArclen(idx, count, totalLength, s)`, `SplineNearest(idx, count, worldPos)`. SM5 fallback via `UZ_SPLINE_BIND` macro.
- [x] 1.4 `RebuildAndUpload` rebuilds the arc-length LUT, bakes one `VfxSplinePoint` per uniform sample, MapBuffer / memcpy / UnmapBuffer once per frame; trailing slots zeroed so the shader never sees stale data when the spline shrinks. Repeated invocations reuse the buffer (no leak — verified by test).
- [x] 1.5 `SpawnAlongSplineModule` — `engine/vfx/modules/spline_modules.{h,cpp}`. `stratified` / `jitter_radius` / `tangent_offset` config + HLSL snippet that distributes spawn positions via `SplineSampleAtU`.
- [x] 1.6 `ForceTowardSplineModule` — spring force pulling particles to the nearest baked sample. `stiffness` / `max_acceleration` / `attract_distance` config + HLSL snippet that uses `SplineNearest` and clamps force magnitude to `max_acceleration`.
- [x] 1.7 `FollowSplineModule` — per-particle `u` advances by `speed × (age / lifespan) + start_u`, optionally looping. Position becomes `SplineSampleAtU(u)`. Velocity is set along the tangent so downstream velocity-aligned modules pick up the heading.
- [x] 1.8 Module registration — three new entries in `engine/vfx/modules/register_builtin_modules.cpp`: `spawn_along_spline`, `force_toward_spline`, `follow_spline`
- [x] 1.9 -> moved to follow-up `phase16_vfx-spline-data-interface-hardware-validation` section 3 (editor "Spline Target" picker depends on a new `SplineComponent` ECS type and a Niagara Parameters panel row — both involve editor runtime that is hardware-pending)
- [x] 1.10 `.uzfx` serialization — modules consume the existing `IVFXModule::ApplyJsonConfig` virtual + `ApplyEmitterStackToModuleStack` helper; round-trips validated by 4 `SplineUzfx.*` tests
- [x] 1.11 Sample assets shipped under `sample/content/vfx/tests/`: `spline_distribute.uzfx` (Spawn module, 200 stratified additive sparks), `spline_attract.uzfx` (Force module, 400 alpha-blended), `spline_follow.uzfx` (Follow module, 100 premul-alpha trail heads)
